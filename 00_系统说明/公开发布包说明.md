# 公开发布包说明

这个文件定义 AI流量团队未来上传 GitHub 时的公开发布口径。

正式名称建议使用“公开发布包”，不要叫“上传文件”。

- “上传”只是把仓库推到 GitHub 的动作。
- “公开发布包”才是别人下载、安装、学习和复用时实际接触到的成品边界。

## 一句话结论

当前仓库采用单主链模式。

外部用户安装 AI流量团队以后，默认直接使用正常工作链路：

- `02_资产中心/01_原始知识库`
- `02_资产中心/02_内容模块库`
- `02_资产中心/03_对标账号库`
- `02_资产中心/04_爆款选题库`
- `02_资产中心/05_爆款开头库`
- `02_资产中心/06_生成正文库`
- `02_资产中心/07_润色成稿库`

只有少量本地隐藏目录不进入 GitHub，例如工作纪实、工作纪实模块和 Agent 运行记录。

项目级默认入口说明：

- 外部用户进入 `AI流量团队` 项目后，默认先按 **小姜** 入口理解正式业务需求
- 用户不需要先知道 Agent 名字，也不需要先学会调 Skill
- 这条规则由项目根目录 `AGENTS.md` 定义，并由现有 Agent 文档和 Skill 合同共同落实
- 这里说的是**项目级默认入口**，不是 Codex 全平台所有新对话的强制接管

## 公开发布包包含什么

公开发布包保留能让别人理解、安装和复用系统的正式主链内容：

- Agent 系统骨架
- Agent 输入合同、输出合同、调用规则
- Skill 武器库结构
- 工作流说明
- 输入输出模板
- 发布检查工具
- 公开安装和使用说明

## 公开发布包不包含什么

公开发布包不包含少量本地隐藏目录和运行记录：

- `02_资产中心/01_原始知识库/99_我的工作纪实`
- `02_资产中心/02_内容模块库/99_工作纪实模块`
- `01_Agent系统/01_小姜-CEO助理Agent/99_本地运行记录`
- `01_Agent系统/02_小审-质量审核Agent/99_审核记录`
- `01_Agent系统/03_小息-信息采集Agent/99_执行记录`
- `01_Agent系统/04_小拆-内容拆解Agent/99_执行记录`
- `03_工作流中心/01_短视频主工作流/99_运行记录`

## 规则同步原则

系统规则不能只写在本地隐藏目录。

- 系统规则、Agent 原则、Skill 调用边界、审核标准、工作流原则必须保存在公开层正式文档中。
- 本地隐藏目录只保存不公开的真实内容和运行记录，不作为规则的唯一来源。
- 如果某条规则只写在本地隐藏目录，公开仓库用户将无法继承这条规则，因此不视为正式规则。
- 后续任何规则修正，都必须同步检查公开层文档是否需要更新。

小姜工作台规则：

- 小姜真实工作台属于作者真实生产状态，默认写入 `01_Agent系统/01_小姜-CEO助理Agent/99_本地运行记录/`
- 每次调用小姜工作台时，除了刷新本地真实工作台，还必须自动执行一次主链同步检查
- 公私模板同步由 `tools/build_xiaojiang_dashboard.py` 触发，并调用 `tools/sync_public_templates.py`
- 正式主链公开；只有本地运行记录目录不进入公开发布包
- 主链中的字段模板、说明文件和工作台模板，都要跟着这次同步自动覆盖更新
- 工作台中非 md 文件不等于残留；只有“已转 md 且审核通过后仍未删”的旧原文件才叫残留

## 本地隐藏模式

本地隐藏模式只解决少量不想公开的内容。

当前固定隐藏内容：

- 工作纪实原文
- 工作纪实模块
- 小姜、小审、小息、小拆运行记录
- 主工作流运行记录

## 外部用户安装模式

外部用户从 GitHub 下载 AI流量团队以后：

- 默认直接在正常链路目录里录入自己的资料、选题、文案和视觉结果
- 如果他们自己也要保护私有资产，可以自行增加新的本地隐藏目录

外部用户的默认写入位置：

| 资产类型 | 默认写入位置 |
| --- | --- |
| 原始资料 | `02_资产中心/01_原始知识库` |
| 内容模块 | `02_资产中心/02_内容模块库` |
| 对标账号资产 | `02_资产中心/03_对标账号库` |
| 爆款选题资产 | `02_资产中心/04_爆款选题库` |
| 爆款开头资产 | `02_资产中心/05_爆款开头库` |
| 正文方案 | `02_资产中心/06_生成正文库` |
| 润色成稿 | `02_资产中心/07_润色成稿库` |

## 发布准备工具

公开发布包准备工具建议固定命名为：

`tools/prepare_public_release.ps1`

它负责：

- 生成临时公开发布目录
- 复制正式主链
- 排除本地隐藏目录
- 排除旧三条历史工作区
- 排除运行缓存和临时文件
- 保留正式资产、说明、Skill 和工具
- 调用公开发布检查脚本

它不负责把仓库上传到 GitHub。

## 发布前必须通过的检查

正式发布前必须确认：

- 本地隐藏目录没有进入公开发布包
- 旧三条历史工作区没有进入公开发布包
- 公开包没有本机绝对路径依赖，例如旧的 `_private` 路径或外部盘符
- 外部用户不会被说明文档误导去使用已退役的私有层
- 外部用户可以直接从正常链路目录开始使用
