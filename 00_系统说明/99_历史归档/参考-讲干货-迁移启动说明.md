# 讲干货-AI流量团队迁移启动说明

这份说明面向“新电脑 + 新 Codex 账号 + 没有聊天上下文”的接手场景。

## 1. 解压后先看哪里

首次打开这套工厂时，按下面顺序阅读：

1. 根目录 `README.md`
2. 根目录 `环境依赖说明.md`
3. 根目录 `Skill接入说明.md`
4. 对应模块的 `00_系统说明/README.md`

不要一上来先运行脚本，先判断这次是“只读使用”还是“需要跑流程”。

## 2. 哪些目录是当前正式模块

当前正式主结构是这 4 个模块：

1. `01_内容模块大师`
2. `02_爆款结构大师`
3. `03_爆款文案大师`
4. `05_视频配图大师`

第一次迁移完成后，只建议先验证这 4 个模块。

## 3. 哪些目录是仓库内规划模块

下面这些目录仍保留在仓库里，是为了记录未来路线图，不代表当前都可独立运行：

1. `06_账号分析大师`
2. `07_视频剪辑大师`
3. `08_视频发布大师`
4. `09_IP3.0定位大师`

## 4. 不装 Obsidian 是否能用

可以。

Obsidian 只是浏览辅助，不是系统前提。即使不安装 Obsidian，也可以：

- 阅读说明文档
- 查看案例与规则
- 使用 `tools` 和 Skill 继续建设

`.obsidian/workspace.json` 只是本机工作区状态，不属于迁移必需文件。

## 5. 新电脑目录是否必须放在固定盘符

不需要。

这套工厂不要求必须放在 `E:\AI流量工厂\讲干货-AI流量工厂`。迁移后可以解压到任意目录，只要目录结构保持完整即可。

## 6. 什么时候需要安装环境

如果只是看内容、看说明、看案例，不需要安装任何开发依赖。

如果要实际运行当前正式流程，至少需要：

- Codex
- Node.js
- Python 3
- PowerShell
- `requirements.txt` 里的 Python 依赖

具体依赖和安装用途见 `环境依赖说明.md`。

## 7. 第一次验证建议先跑哪条链路

建议先检查最短主链路：

1. 看懂 `01_内容模块大师` 的输入库、处理库、输出库关系
2. 看懂 `02_爆款结构大师` 的输入库、结构库关系
3. 看懂 `03_爆款文案大师` 如何调用结构库和内容模块资产生成新文案
4. 看懂 `05_视频配图大师` 如何通过 `IP视觉PPT生成Skill` 生成整页 PNG 配图

如果只是验证迁移是否成功，做到“入口清楚、路径能定位、模块关系能讲清”就够了。

## 8. 推荐操作顺序

1. 解压到任意目录
2. 阅读根目录说明
3. 判断本次是只读还是继续建设
4. 如果继续建设，先装环境
5. 按 `Skill接入说明.md` 接入核心 Skill
6. 先验证当前正式模块，再考虑规划模块

## 9. 打包边界

迁移包默认保留：

- `01_内容模块大师`
- `02_爆款结构大师`
- `03_爆款文案大师`
- `05_视频配图大师`
- `10_Skills武器库`
- `tools`
- 根目录说明文件
- `requirements.txt`

迁移包默认排除：

- `06-09`
- `.git`
- `.obsidian/workspace.json`
- `.obsidian/graph.json`
- 其他只影响个人视图的本机状态文件

## 10. 打包执行规则

这套工厂的原始工作区是母本。

以后重新打包时，固定流程如下：

1. 先复制一份临时打包目录
2. 只在临时目录里做案例裁剪
3. 原始工作区不做删除
4. 打包完成后，临时目录可删
5. 母本始终保持完整

案例“每目录最多 3 份主案例”的规则，只用于迁移包副本，不用于原始仓库。

实际操作时，统一使用 [tools/prepare_safe_package.js](/E:/AI流量工厂/讲干货-AI流量工厂/tools/prepare_safe_package.js) 先准备临时打包目录。

每次正式版本打包完成后，都要在根目录补一份对应版本的简短更新说明，例如 `版本更新说明-v2.4.md`，并随迁移包一起带出。

## 11. 标准触发方式

未来如果你说：

**按既定规则打包**

默认表示：

1. 按本说明准备临时打包副本
2. 只带当前正式模块、`10_Skills武器库`、`tools`、根目录说明与 `requirements.txt`
3. `06-09` 不打包
4. 当前正式模块的输入/输出案例目录只在副本里每目录最多保留 3 个主案例
5. 默认不自动重新压缩
