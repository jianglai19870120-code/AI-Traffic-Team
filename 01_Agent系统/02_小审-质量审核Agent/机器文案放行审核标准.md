# 机器文案放行审核标准

审核对象：

- `02_资产中心/06_生成正文库`

当前重点：

- `02_资产中心/06_生成正文库/01_干货型文案`

审核目标：

判断一份正文方案文件能不能正式进入成稿阶段，而不是把结构失真、模块失真或明显中间态的方案继续交给 `爆款开头成稿生成Skill`。

固定审核项：

## 一、文案阶段是否正确

- 是否明确属于 `06_生成正文库` 的正文方案，而不是最终成稿
- 是否已经按当前链路生成到正式目录
- 是否不是临时草稿、口头备注或半截提纲

## 二、文件合同是否成立

- 文件名是否为 `选题_YYYY-MM-DD_HH-mm-ss.md`
- H1 是否与文件名主体一致
- 是否固定包含 `文案结构：干货型`
- 是否固定只输出一条主线和一张四列表
- 是否没有残留旧 `三套方案 / 方案1 / 文案润色 / 爆款开头复刻`

## 三、11 行结构是否成立

- 表格字段是否固定为：
  - `序号`
  - `逻辑关系`
  - `选用模块`
  - `对应来源`
- 是否固定 11 行：
  1. `误区1`
  2. `误区2`
  3. `过渡句`
  4. `步骤1`
  5. `步骤2`
  6. `步骤3`
  7. `过渡句`
  8. `步骤1`
  9. `步骤2`
  10. `步骤3`
  11. `金句收口`
- 第 3 行和第 7 行是否为过渡句，而不是伪装成模块
- 第 4-6 行是否共同解决第一个问题
- 第 8-10 行是否共同解决第二个问题
- 两组问题是否存在递进关系，而不是简单并列

## 四、模块调用是否真实可用

- 非过渡句行是否都有明确 `选用模块`
- 非过渡句行是否都有明确 `对应来源`
- 是否不是只写模块标题、没有实际内容
- 是否没有明显“待补 / 待找 / 待确认 / 后面再写”这类中间态

## 五、是否值得进入成稿阶段

- 是否已经能看出完整主线
- 是否能看出误区 -> 解决问题一 -> 解决问题二 -> 收口的结构
- 是否已经达到让成稿 Skill 继续润色的最小门槛

通过条件：

- 文案阶段正确
- 文件合同成立
- 11 行结构成立
- 模块调用真实可用
- 达到进入成稿阶段的最小门槛

退回类型：

- 退回小写补正文结构
- 退回小拆补模块支撑
- 退回小策重看选题主线
- 如问题属于长期质量要求，转入规则升格判断

补充边界：

- 小审不直接改正文方案
- 小审只判断这版正文方案能不能正式进入成稿阶段
- 正文方案不通过，不允许进入 `07_润色成稿库`
