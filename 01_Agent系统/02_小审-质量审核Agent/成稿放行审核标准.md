# 成稿放行审核标准

审核对象：

- `_private/assets/07_润色成稿库`

当前重点：

- `_private/assets/07_润色成稿库/01_干货型成稿`

审核目标：

判断一份最终成稿能不能正式进入下游使用，而不是把结构被改乱、口播不可读或开头正文脱节的稿子当成正式资产。

固定审核项：

## 一、文案阶段是否正确

- 是否明确属于 `07_润色成稿库` 的最终成稿
- 是否不是 `06_生成正文库` 的正文方案原件
- 是否已经完成开头匹配与全文润色

## 二、文件合同是否成立

- 文件名是否为 `选题_YYYY-MM-DD_HH-mm-ss.md`
- H1 是否与文件名主体一致
- 是否固定包含：
  - `文案结构：干货型`
  - `开头卡片编号：BKxxx`
- 是否不再输出表格
- 是否不再输出模块来源分析、匹配过程和旧三方案

## 三、开头结构是否被保留

- 是否能看出一个完整的爆款开头段
- 是否没有丢失 BK 卡片约束下的开头推进结构
- 是否不是只把 BK 编号挂上去，但正文里没有真正形成开头

## 四、正文顺序是否被保留

- 是否仍然先讲误区，再进入第一组解决路径，再进入第二组解决路径，最后金句收口
- 是否没有把两组步骤问题混写成一团
- 是否没有把过渡句删掉后直接跳段
- 是否没有把正文方案改成另一套逻辑

## 五、口播可用性是否达标

- 是否更接近短视频口播，而不是表格或说明书
- 是否具备笃定感和口语化表达
- 是否有自然的长短句切换
- 是否没有明显 AI 味、堆砌感、过度书面化
- 是否没有明显占位符、中间态或自我说明

## 六、是否可进入正式使用

- 是否已经能直接拿去录口播或继续下游处理
- 是否不需要再依赖额外口头解释才能理解
- 是否没有明显合同错误、结构错误或元信息缺失

通过条件：

- 文案阶段正确
- 文件合同成立
- 开头结构与正文结构都未被打乱
- 口播可用性达标
- 可正式进入下游使用

退回类型：

- 退回小写补成稿润色
- 退回小镜重看 BK 开头卡片匹配
- 退回小策重看主线
- 如问题属于长期质量要求，转入规则升格判断

补充边界：

- 小审不直接改成稿
- 小审只判断是否允许作为正式成稿进入下一步
- 成稿不通过，不允许伪装成正式可用资产
