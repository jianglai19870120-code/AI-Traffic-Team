# 正式模块放行审核标准

审核对象：

- `02_资产中心/02_内容模块库`
- 当前重点：`02_资产中心/02_内容模块库/01_干货型内容模块`

审核目标：

判断拆解结果能不能成为正式可复用内容模块，而不是一次性中间草稿。

固定审核项：

## 一、模块归位是否正确

- 是否放到了正确的内容类型目录下
- 是否放到了正确的模块子类下
  - 金句模块
  - 误区模块
  - 步骤模块
- 是否没有混入选题、对标结构、文案成稿内容
- 是否能关联到具体原始资料来源

## 二、模块内容是否可复用

- 是否不是对原文的机械摘抄
- 是否已经整理成后续文案可直接调用的表达
- 是否能够独立成立，而不是必须依赖上下文才看得懂
- 是否能看出该模块到底在讲什么

## 三、模块类型是否匹配

- 金句模块是否确实是高传播表达，而不是普通说明句
- 金句正文是否不超过 30 个汉字；长度只计算 `——《书名》` 前面的正文
- 金句是否是完整短句、笃定句，而不是普通描述句、摘要句、解释句
- 金句正文是否没有 `本书 / 作者 / 原文 / 书中 / 提到 / 认为` 等来源叙述
- 金句是否没有链接、年份、英文案例残片、冒号引文、人物称呼、访谈说明、发布说明等原文残留
- 金句是否不是半句残句，例如句尾停在 `的 / 了 / 和 / 与 / 及` 等不完整语义
- 误区模块是否确实在指出错误认知，而不是泛泛观点
- 误区模块是否像面向观众的认知纠偏文案，而不是书摘解释
- 步骤模块是否确实能形成动作路径，而不是空泛建议
- 步骤模块是否像执行说明文案，而不是证据说明或书籍依据说明
- 每个误区文件是否使用 `误区1 / 误区2 / 误区3` 这类连续结构展开，且数量为 2-3 个
- 每个步骤文件是否使用 `步骤1 / 步骤2 / 步骤3 / 步骤4` 这类连续结构展开，且数量为 2-4 个
- 每个误区 / 步骤编号块正文是否至少有 3 句拓展
- 每个误区 / 步骤编号块正文是否没有重复编号标题
- 步骤模块标题是否是具体执行问题、决策问题、机制问题或明确动作标题
- 是否存在同一本书旧产物和新产物重复混杂

## 三B、拆解是否充分

- 是否存在充分拆解记录
- 是否扫描了整本书，而不是只抽样或套模板
- 是否记录了原始资料字数 / 段落数
- 是否记录了误区候选、步骤候选、金句候选数量
- 是否记录了最终入库数量和丢弃原因
- 是否分别记录了误区候选池和步骤候选池，而不是共用一个主题池
- 是否存在固定 4+4、12+12、13+13 或其他误区 / 步骤数量配平的模板化痕迹
- 是否存在误区候选池和步骤候选池完全同源或高度重合
- 是否存在为了让误区和步骤数量一致，把没有真实步骤依据的主题硬写成步骤
- 是否命中标题模板：`以为X可以靠想象直接做对`、`怎么把X变成可验证的行动`、`X要先被验证`、`X要靠行动验证`
- 模块标题是否与书本内容强相关，而不是通用创业话术
- 误区标题是否是具体错误认知，而不是原文残片、人名案例、泛主题词或统一句式套壳
- 步骤标题是否是具体执行问题，而不是 `如何处理X`、`怎么X` 这类没有明确执行对象的套壳句
- 步骤标题是否出现 `怎么怎么`、`如何怎么` 等重复前缀
- 同一本书的步骤标题问法是否被统一套成单一 `怎么...` 模板
- 步骤标题是否只是泛泛提问，而没有明确动作对象、决策分叉或机制焦点
- 充分拆解主题池是否包含 `北京 / 比如 / 因此 / 问题 / 樊登老师` 这类地点、人名、连词、泛词、高频噪声词
- 是否存在同一本书多个模块主题重复，或只是把同一套通用创业话术换词展开
- 如果缺少充分拆解记录、疑似模板化生成或明显拆少，直接退回小拆

## 三C、误区和步骤是否独立成立

- 误区数量和步骤数量不要求一致，也不应默认一致
- 误区必须是明确错误认知、错误做法或错误判断
- 步骤必须是书中确实能形成执行链的解决方案
- 同一主题可以只有误区、只有步骤，或两者都没有
- 如果步骤只是把误区标题改写成行动句，直接退回小拆
- 如果误区标题和步骤标题只是同一批主题换壳，直接退回小拆
- 如果审核报告只能写“未通过”但不能指出旧合同、数量配平、候选池同源、模板标题、正文来源叙述或金句残片等具体阻断原因，视为审核不完整，退回小审补审

## 三A、正文表达是否可直接调用

- 模块正文必须像短视频可调用内容资产
- 正文区不得出现以下来源叙述词：
  - `这本书`
  - `本书`
  - `作者`
  - `书中`
  - `原文`
  - `依据`
  - `提到`
  - `认为`
  - `强调`
- 来源只允许出现在底部元信息、正式产物来源记录和模块索引中
- 如果正文仍然像“书籍解释 / 依据说明”，直接退回小拆

## 四、来源可追溯性是否可用

- 是否能回溯到原始资料来源
- 是否没有丢失基本来源关系
- 是否没有因为迁移或重命名导致来源断裂

## 五、正式资产质量是否达标

- 是否不是明显半成品
- 是否没有残留“待补充”“以后再写”“临时草稿”等中间态痕迹
- 是否满足进入正式模块库的最小可用门槛

通过条件：

- 模块归位正确
- 模块类型匹配
- 模块内容可复用
- 来源关系可追溯
- 没有明显中间态痕迹

退回类型：

- 退回小拆重归类
- 退回小拆补模块表达
- 退回小拆补来源关系
- 退回小拆清理中间态草稿痕迹
- 如发现是规则缺失，不直接只退当前模块，转交小姜判断是否进入规则升格

补充边界：

- 小审不重复代替小拆做拆解
- 小审重点审“能不能正式进入模块库”
- 如果问题已经反复出现，默认提醒小姜判断是否应升格为长期规则
- `标签字典` 当前不作为正式模块放行条件
- `模块索引` 只作为机器检索清单和来源核对依据
