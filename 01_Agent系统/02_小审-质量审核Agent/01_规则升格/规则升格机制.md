# 小审规则升格机制

## 目标

把“用户这次明确确认过的新质量要求”，沉淀成下次默认执行的长期规则。

## 什么情况下进入规则升格

满足下面任一情况，默认进入规则升格判断：

1. 用户明确说“以后都应该这样做”
2. 用户明确指出同类问题不希望下次再重复说明
3. 当前问题已经不是单次修补，而是正式质量门槛
4. 这条要求会影响多个资产层或多个 Agent

## 小审的固定判断

收到规则候选项后，小审要判断：

1. 这是单次修改，还是长期规则
2. 它影响的是哪一层  
   - 书源目录  
   - 原始资料  
   - 内容模块  
   - 对标结构  
   - 文案  
   - 视觉  
   - 路由 / 协作
3. 它是否和现有规则重复
4. 它是否需要被写成正式审核标准

## 升格后的固定动作

一旦判定升格：

1. 记录到 `规则升格记录.md`
2. 通知小姜同步写入程序记忆
3. 如有必要，要求相关 Agent 更新自己的调用规则或审核标准

## 不升格的情况

- 只是当前一次性的人工偏好
- 不具备复用价值
- 不影响正式放行标准
- 只是某个临时文件的局部写法
