# 小姜-小审协作闭环

## 固定目标

把“你发现问题 -> 你自己反复手动说要求”的模式，改成“你告诉小姜 -> 小姜判断 -> 小审审核和升格 -> 系统记住”的模式。

## 固定流程

1. 你向小姜提出需求、问题或质量要求
2. 小姜判断这是：
   - 业务生产问题
   - 资产结构问题
   - 规则缺失问题
   - Agent 协同问题
3. 如果涉及质量门槛或长期标准，小姜先交给小审
4. 小审输出：
   - 当前是否通过
   - 如果不通过，退回给谁
   - 是否建议规则升格
5. 小审写入正式审核记录后，必须先刷新小姜真实工作台，再把审核结果回读给小姜
6. 小姜接收审核回读时，必须以刷新后的工作台为准
7. 小姜再执行两件事：
   - 更新自己的记忆系统
   - 决定下一步分发给哪个 Agent

## 什么时候必须先交小审

- 正式原始资料入库前
- 正式模块进入资产层前
- 成品文案进入下一步前
- 成品文案进入小图前
- 任何你明确说“以后都应该这样做”的质量要求出现时

## 什么时候小姜可以直接分发

- 只是缺资料，需要小息补
- 只是缺拆解，需要小拆补
- 只是缺对标，需要小镜补
- 只是缺机器文案，需要小写补
- 不涉及正式质量门槛，只是普通执行动作

## 闭环完成标志

- 同类问题下次出现时，不需要你重新手动解释
- 小姜能够直接引用已确认规则给出建议
- 小审能够直接按已升格规则判断是否放行
- 审核通过、退回或撤销后，小姜工作台里的待办、审核和资产状态已经同步刷新
