# 短视频主工作流

## 核心原则

短视频主工作流采用：

用户需求 → 小姜岗位分配 → Agent 自治调用 Skill / 工具 → 小审审核 → 小姜回收结果。

小姜只判断该找哪个 Agent，不写死每个 Agent 内部调用步骤。

## V1 主链路

1. 用户把资料、选题或目标告诉小姜。
2. 小姜判断任务类型，并分配给负责 Agent。
3. 如果是原始资料标准化，交给小息。
4. 如果是内容拆解，交给小拆。
5. 如果是对标结构研究，交给小镜。
6. 如果是选题分析，交给小策。
7. 如果是机器文案生成，交给小写。
8. 如果是视觉生成，交给小图。
9. 如果是复盘分析，交给小数。
10. 每个 Agent 自己读取 `能力清单.md` 和 `调用规则.md`，决定调用哪个 Skill / 程序 / 工具。
11. 正式成果生成后，必须交小审审核。
12. 小审通过后，小姜回收结果并向用户汇报。

## 书类资料链路示例

1. 小姜判断：这是书类资料进入内容模块链路。
2. 小姜分配小息确认原始资料是否标准化、是否通过入库审核。
3. 小息自己判断是否调用原始资料标准化能力。
4. 小审审核原始资料。
5. 小姜分配小拆做整本书内容拆解。
6. 小拆自己判断调用 `书籍内容模块拆解Skill`。
7. 小审审核拆解成果。
8. 小姜回收结果。

## 干货机器文案链路示例

1. 小姜判断：这是机器文案生成任务。
2. 小姜分配小写。
3. 小写自己判断是否调用 `干货型文案生成Skill`。
4. 小审审核机器文案。
5. 用户人工优化成品文案。
6. 成品文案再交小审判断是否允许进入视觉。
7. 小图只读取通过审核的成品文案。

## 固定禁止

- 小姜不得越权代替 Agent 执行。
- Agent 没有对应能力时不得硬做。
- 没有审核能力时不得进入正式资产。
- 小图不得读取机器文案。
- 未经小审放行的成果不得进入下一步。

## 当前 V1 边界

- 小剪和小发已经预留岗位，但不在 V1 主链路内强制启用。
- 这份工作流是内部验证链，不是首发对外演示链。
- 首次正式发布前，至少要按 `../短视频主工作流验证清单.md` 跑通 1 次。
