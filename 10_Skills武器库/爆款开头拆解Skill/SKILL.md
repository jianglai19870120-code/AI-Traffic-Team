# 爆款开头拆解Skill

工作区根路径统一取自环境变量 `AI_TRAFFIC_FACTORY_ROOT`；未设置时使用当前工作区根目录。

## 运行模式

本机私有模式：

- 账号表目录：`02_资产中心/03_对标账号库`
- 选中清单：`02_资产中心/05_爆款开头库/00_爆款开头选中清单.md`
- 输出目录：`02_资产中心/05_爆款开头库`

对外公开模式：

- 账号表目录：用户通过 `--input-dir` 传入
- 选中清单：用户通过 `--selection-file` 传入
- 输出目录：用户通过 `--output-dir` 传入

正式输入关系：

- 原文案来源：博主对标表格中的 `文案` 列
- 选题来源：博主对标表格中的 `视频信息` 列
- 选择入口：独立外部选中清单
- 不修改原始 xlsx
- 默认情况下，`00_爆款开头选中清单.md` 由上游选题表中的 `选中开头` 自动同步生成
- 脚本运行后会回写 `00_爆款开头选中清单.md` 的 `状态 / 备注`

## Skill 目标

把一条完整短视频文案拆成一张可供后续匹配和复刻的“爆款开头卡片”。

固定完成七件事：

1. 从完整文案中提取最开始的 `5` 个完整口播功能句；
2. 判断每句话的唯一核心功能；
3. 提炼每句话的可复刻写作结构；
4. 总结五句推进逻辑；
5. 提炼五句结构骨架和可复刻句式模板；
6. 判断唯一一种适合承载的论证方式；
7. 写出未来调用这张开头卡片时的匹配和复刻规则。

本 Skill 只做第一阶段建库，不做新选题复刻。

## 输入要求

账号级 `xlsx` 必需字段：

- `视频信息`
- `点赞数`
- `文案`

账号级 `xlsx` 可选字段：

- `链接`
- `发布时间`
- `内容类型`

外部选中清单字段：

- `序号`
- `选题`
- `链接`
- `状态`
- `备注`

状态定义：

- `待拆解`：允许正式处理
- `已拆解`：已生成正式 BK 卡片，默认跳过
- `拆解失败`：已记录失败原因，默认跳过，待人工改回 `待拆解` 再重跑

命中规则：

1. 优先按 `链接` 精确命中账号表原始记录；
2. 没有 `链接` 时，按 `选题` 在全部账号表里回查原始 `视频信息`；
3. `链接` 和 `选题` 同时为空时，该行无效；
4. 如果无链接且多个账号表存在同题记录，必须在清单补充链接，不自动猜。

运行结果回写规则：

- 成功生成 BK 卡片后，回写：
  - `状态 = 已拆解`
  - `备注 = 已生成 BKxxx`
- 单条失败时，不中断整批；回写：
  - `状态 = 拆解失败`
  - `备注 = 失败原因`
- 小拆先把卡片写入候选区，小审通过后才覆盖正式 BK 文件。
- 小审退回时保留候选文件和审核报告，不把低质量卡片混入正式库。

## 前5句定义

“前5句话”不是按逗号、句号、字数机械切分，而是：

> 文案开头最先出现的5个完整口播功能句。

一个完整口播功能句必须承担一个相对完整的表达任务，例如：

- 提出问题
- 抛出结果
- 描述现象
- 引用数据
- 列举案例
- 制造悬念
- 给出判断
- 推演后果
- 预告内容
- 提醒风险

一句话中可以有多个逗号；只要这些分句共同完成同一个表达任务，就算一句。

强制边界：

- 一个功能句只能有一个核心判断、结果、案例或动作。
- 两个独立意思即使没有标点，也必须拆开。
- 原因和限定条件只有在服务同一核心功能时才能保留。
- 超过 70 个汉字必须重新检查语义边界。
- 超过 100 个汉字直接判定为切分失败，不允许进入正式库。

## 前5句切分规则

规则1：先修复文本，再切分。

允许：

- 修正明显错别字；
- 补充必要标点；
- 调整明显错误断句；
- 清理不承担表达功能的开头口癖。

不允许：

- 改写原意；
- 美化表达；
- 删除有效信息；
- 总结原文观点；
- 为凑够5句编造内容。

规则2：标题默认不算一句。

如果开头出现 `选题：`、`标题：`、`备注：` 等文档信息，不属于实际口播内容，不计入前5句；如果标题本身就是视频里说出的第一句话，则正常计入。

规则3：优先按表达任务切分。

完整问题、完整判断、完整数据、完整案例、完整结果推演、完整内容预告，都可以独立算一句。

规则4：补充说明不单独切分。

如果后半句只是解释、限定或补充前半句，两部分共同完成一个功能，则保留为一句。

规则5：极短承接词不单独算一句。

`能`、`对`、`是`、`没错`、`好`、`那么`、`所以` 这类承接词通常与后一句合并；如果 `为什么？` 这类短句本身承担明确悬念功能，可以独立算一句。

规则6：一句话包含两个独立功能时必须拆开。

例如“我们真的要提前为自己想想出路了，前段时间我看了一份报告……”应拆为“危机提醒”和“数据证明”两句。

规则7：不足5句不得补写。

原文实际只有3句或4句时，只分析实际存在的句子。

规则8：ASR 缺标点时按语义补切。

优先检查主语变化、转折、因果、结果、案例、时间和动作变化。不能因为原稿没有句号，就把多个完整意思合并为一句。

## 逐句拆解规则

每句话只判断一个最主要的核心功能。

优先使用以下具体功能名称：

- 利益承诺
- 结果承诺
- 危机提醒
- 风险警告
- 人群点名
- 身份代入
- 痛点描述
- 现象描述
- 场景引入
- 认知提问
- 悬念追问
- 反常识判断
- 数据引入
- 数据证明
- 案例引入
- 案例证明
- 连续确认
- 时间对比
- 结果对比
- 权威背书
- 降低门槛
- 放大后果
- 趋势推演
- 内容预告
- 方法预告
- 降低防备
- 观点收束
- 冲突制造
- 故事引入
- 结果悬念
- 经历背书
- 质疑回应
- 可行性证明
- 身份冲突
- 规则反转

禁止使用 `吸引用户`、`制造共鸣`、`增强效果`、`引起兴趣`、`承上启下` 等无法指导复刻的模糊标签。

`内容预告` 只用于明确说明“接下来讲什么”的句子。无法稳定判断功能时必须退回人工处理，禁止把 `内容预告` 当成默认值。

## 写作结构规则

写作结构必须是可替换、可复用的公式。

固定写法：

`元素A＋元素B＋元素C`

允许2到4个元素，不要过度拆分。

正确示例：

- `明确时间＋低门槛结果＋机会方法预告`
- `目标结果＋两个认知选项＋直接提问`
- `信息来源＋现实趋势＋具体预测数据`
- `过去时间与数据＋当前时间与数据＋增长对比`

错误示例：

- `提出赚钱问题`
- `用数据吸引观众`
- `制造共鸣`
- `关键信息＋表达动作＋句内承诺`

## 五句推进逻辑

只输出前5句内部的核心功能链：

`第1句功能 → 第2句功能 → 第3句功能 → 第4句功能 → 第5句功能`

推进逻辑必须与逐句拆解中的核心功能完全一致。

## 五句结构骨架

每张开头卡片必须输出 `五句结构骨架`，用于后续复刻。

这一段固定包含两部分：

1. 五句抽象结构：说明每一句“先给出什么、再补什么、追问什么、用什么证明、推演什么结果”。
2. 句式模板：用 `【变量】` 标出未来可以替换的位置。

禁止输出：

- `第N句保留某功能`
- `按某结构替换为新正文素材`
- 没有真实句法、只有抽象标签的空模板

例如 `数据＋时间对比＋趋势推演` 类型必须输出：

```markdown
### 4. 五句结构骨架

1. 先给出一个关于个人未来的警告
2. 引用一份报告或数据，抛出异常变化
3. 追问这个数字意味着什么
4. 用过去和现在的数据进行对比
5. 按照当前速度推演未来，得出一个严重结果

句式模板：

1. 我们真的要提前为自己想想【出路／应对办法】了。
2. 前段时间我看到一份报告，说【某个群体／某种现象】在今年很有可能达到【惊人数据】。
3. 这是什么概念呢？
4. 这个数字在【过去时间】才只有【过去数据】，到了【最近时间】已经达到【当前数据】。
5. 如果今年真的达到【目标数据】，那么按照这个速度继续发展，再过【时间】，就意味着【与普通人密切相关的严重结果】。
```

## 适合承载的论证方式

只输出一种主要论证方式，用于后续“开头生成Skill”检索和匹配。

常见论证方式：

- 历史案例＋连续追问
- 数据＋时间对比＋趋势推演
- 现实痛点＋连续提问
- 个人故事＋冲突悬念
- 旧认知＋直接纠偏
- 两种路径＋结果对比
- 权威观点＋现实解释
- 结果承诺＋方法预告
- 具体场景＋身份代入
- 异常现象＋原因悬念
- 失败案例＋反向证明
- 成功案例＋结果证明
- 个人经历＋结果反差
- 常见选择＋后果对比

判断论证方式时看“主要证明路径”，不要看选题关键词。

如果功能链无法对应到一条真实证明路径，整张卡片退回，不使用默认论证方式。

## 调用匹配规则

每张开头卡片必须输出 `调用匹配规则`，用于后续文案生成 Skill 从 100 个或 1000 个开头里选中最合适的一张。

固定包含：

- `适合的新正文`
- `需要具备的素材条件`
- `不适合的新正文`
- `复刻时必须保留`
- `复刻时禁止`

核心原则：

- 不按选题关键词匹配；
- 先看新正文核心结论；
- 再看新正文主要论证方式；
- 最后看正文素材能否自然填满这张卡片的五句模板。
- 调用条件必须写出真实素材要求，例如经历次数、案例数据、身份冲突、时间对比或可交付工具。
- 禁止只写“与该论证方式接近”或“能自然承接功能链”。

## 小审正式放行

小审固定检查：

- 每个功能句能否回指清洗后的原文；
- 是否存在超长句、多义句或 ASR 残片；
- 核心功能是否具体、唯一；
- 写作结构是否来自原句真实元素；
- 骨架和模板是否可直接填充；
- 论证方式是否与五句推进链一致；
- 调用匹配规则是否能排除素材不足的正文。

只有审核结论为 `通过` 才写入正式 BK 库并回写 `已拆解`。审核退回时回写 `拆解失败` 和明确原因。

## 正式输出

每条命中记录生成1个独立文件。

编号规则固定为全库统一递增：

- `BK001`
- `BK002`
- `BK003`

同一 `博主名 + 选题名` 已存在时，覆盖更新原文件，不重复占用新编号。

文件名格式：

- `BK001_博主名_选题名.md`

单文件固定包含：

1. `### 1. 原文前5句`
2. `### 2. 逐句拆解`
3. `### 3. 五句推进逻辑`
4. `### 4. 五句结构骨架`
5. `### 5. 适合承载的论证方式`
6. `### 6. 调用匹配规则`

## 禁止事项

- 不分析第6句及后续正文。
- 不判断完整开头到哪里结束。
- 不总结整条短视频观点。
- 不分析完整正文结构。
- 不评价文案好坏。
- 不提出优化建议。
- 不复刻新选题。
- 不输出多个论证方式。
- 不输出复杂评分。
- 不根据关键词判断论证方式。
- 不把无法识别的句子默认标记为内容预告。
- 不输出超过 100 个汉字的功能句。
- 不输出空占位结构骨架和句式模板。
- 不省略五句结构骨架。
- 不省略调用匹配规则。
- 不改变正式路径和字段合同。
