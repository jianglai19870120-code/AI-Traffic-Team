# 安装化契约

当前阶段只做“安装化契约”，不做“完整公开可安装发布”。

## 当前目标

现在要锁定的是：

- 每个 Skill 未来对外发布时必须长什么样
- 哪些目录和文件可以公开
- 哪些路径必须从旧私有路径里抽离
- 哪些 Skill 还处于“待删减合并后定版”

现在不要做的是：

- 最终安装脚本
- 最终一键发布包
- 最终首发样板数量
- 最终外部用户演示链

## 每个 Skill 的最低结构

当前最低必备：

- `SKILL.md`
- `migration.json`

首次正式发布前必须补齐：

- `README.md`
- `输入说明.md`
- `输出说明.md`
- `依赖说明.md`
- `公开状态.md`

可选但推荐：

- `references/`
- `scripts/`
- `examples/`

## 路径约束

Skill 对外发布前，不允许继续依赖：

- `<作者旧讲干货工作区路径>`
- `<作者旧热门播客工作区路径>`
- `<作者旧推荐型工作区路径>`
- 已退役的旧私有层路径
- 作者个人环境目录

发布前要改成两类路径：

- 仓库公开样板路径
- 用户自行提供的输入路径

## 发布状态字段

每个 Skill 的 `公开状态.md` 未来统一使用这 4 个状态之一：

- `仅内部使用`
- `待删减合并`
- `安装契约已锁定`
- `可公开安装`

## 对外发布前的通过条件

单个 Skill 只有在同时满足下面条件后，才能进入首次正式发布包：

- 名称和边界已经稳定
- 不再依赖作者私有数据路径
- 输入输出说明完整
- 至少有 1 个公开样板可演示
- 能被陌生用户看懂如何开始使用
