# 爆款开头成稿生成Skill

工作区根路径统一取自环境变量 `AI_TRAFFIC_FACTORY_ROOT`；未设置时使用当前 AI 流量工厂根目录。

## 何时调用

当用户明确点名 `爆款开头成稿生成Skill`，或者手动输入选题表中某条记录已经完成正文方案生成、需要继续生成最终成稿时，调用本 Skill。

正式入口：

- `_private/assets/04_爆款选题库/00_手动输入选题表.md`

正文方案来源：

- `_private/assets/06_生成正文库`

爆款开头卡片来源：

- `_private/assets/05_爆款开头库`

成稿输出目录：

- `_private/assets/07_润色成稿库`

## 输入契约

手动输入选题表字段固定为：

- `序号`
- `文案结构`
- `选题`
- `正文时间`
- `正文状态`
- `成稿时间`
- `成稿状态`

字段职责固定为：

- `正文时间 / 正文状态`：只记录正文方案是否生成
- `成稿时间 / 成稿状态`：只记录最终成稿是否生成

默认读取第一条满足以下条件的记录：

- `文案结构=干货型`
- `正文状态=已生成`
- `成稿状态` 为空

如果用户显式指定选题，则按该选题生成；即使该选题已有 `成稿状态=已生成`，也按用户要求重新生成新文件，并把同名记录回写为最新 `成稿时间` 和 `成稿状态=已生成`。

成稿文件生成后，必须立刻调用：

```text
E:\AI流量工厂\01_Agent系统\02_小审-质量审核Agent\scripts\audit_final_drafts.py --file <新生成文件绝对路径> --write-report
```

只有审核通过，才允许把手动输入选题表回写为：

- `成稿时间=本次时间戳`
- `成稿状态=已生成`

如果审核退回，则必须回写为：

- `成稿时间=本次时间戳`
- `成稿状态=退回修改`

并明确告知退回原因，不允许把未通过小审的成稿伪装成正式可用资产。

## 文案结构路由

先读取 `文案结构`，再决定去哪个正文方案目录取稿。

当前正式支持：

- `文案结构=干货型` -> `_private/assets/06_生成正文库/01_干货型文案`

后续若新增其他文案结构，再补对应映射；当前版本不强行兼容未实现类型。

正文方案选择规则：

- 按选题匹配
- 取同名选题的最新时间戳文件作为正式输入
- 找不到正文方案时，直接报合同错误，不猜测、不降级

## 开头匹配规则

匹配输入不只看选题，而是同时看：

- 选题
- 正文方案里的 `主线`
- 正文方案里的误区、步骤、过渡句、收口结构
- 正文实际想证明的核心结论

匹配流程固定为：

1. 读取正文方案，提炼：
   - 核心结论
   - 主要论证方式
2. 遍历 `05_爆款开头库` 中的 `BK` 开头卡片
3. 优先读取每张卡片的：
   - `### 4. 五句结构骨架`
   - `### 5. 适合承载的论证方式`
   - `### 6. 调用匹配规则`
4. 先筛掉 `不适合的新正文`
5. 再检查 `需要具备的素材条件` 是否被当前正文满足
6. 再检查 `复刻时必须保留` 是否能被当前正文承接
7. 只选中 1 张最匹配卡片

匹配原则固定为：

- 优先匹配正文真实论证方式
- 不按选题关键词硬搜
- 没有数据就不能套数据推演型
- 没有旧认知冲突就不能套直接纠偏型
- 没有连续案例就不能套历史追问型
- 不允许为了套开头去编造正文里不存在的数据、案例、人物经历

如果没有任何卡片能自然匹配，必须明确输出失败原因，不强行成稿。

## 成稿生成规则

本 Skill 不是重写正文，而是在不打乱结构的前提下，把“开头卡片 + 正文方案”转成最终口播成稿。

开头部分必须：

- 严格保留所匹配 `BK` 卡片的五句结构
- 严格保留卡片的推进逻辑
- 严格遵守卡片的 `调用匹配规则`
- 如果卡片已经给出“句式模板”，必须逐句按模板填空复刻
- 只允许根据当前正文语义填写 `【】` 变量
- 不允许重写句型
- 不允许改句序
- 不允许额外扩写成别的开头结构

句式模板优先级高于模型表达习惯。只要 `BK` 卡片已经写明模板，就必须模板优先，而不是“理解后自由改写”。

例如当卡片已经明确给出以下五句模板时：

1. `【大家习惯理解的事情】其实是可以【反常识动作】的，而且可以【强化表达】。`
2. `这条内容可能会【内容长度或表达状态】，我也不一定会【标准化准备】。`
3. `我们就【轻松口语化推进方式】。`
4. `但这件事一定会【继续展开或强调长度】。`
5. `至于【外部数据或表面指标】，我没那么在意，因为【降低功利期待的理由】。`

则最终成稿中的开头五句必须严格沿用这五个句式，只替换 `【】` 中的变量内容，不允许自行改写成别的句型。

正文部分必须：

- 严格保留 `06_生成正文库` 中已有的逻辑顺序
- 误区仍先讲误区
- 两组步骤仍是两个问题、两段递进
- 过渡句仍承担承接作用
- 金句仍用于收口
- 正文中的结构句必须整句加粗

润色目标固定为：

- 笃定
- 口播化
- 口语化
- 长短句切换更自然

当前正文结构句加粗范围固定为：

- 误区起手句，如：`**第一个误区，是……**`
- 第二个误区起手句，如：`**第二个误区，是……**`
- 步骤起手句，如：`**第一步，你要……**`、`**第二步，你要……**`
- 从第一组问题推进到第二组问题的结构推进句，如：`**当这件小事已经能跑出结果，第二个问题才会出现。**`

这里的加粗规则是“整句加粗”，不是只加粗“第一个误区”“第二步”几个字。

禁止：

- 改变开头结构
- 改变正文逻辑结构
- 把两组步骤问题混在一起
- 把表格内容重新解释成另一套逻辑
- 把模块里的意思改偏
- 额外扩写成完整长文课程稿
- 在 `06_生成正文库` 阶段提前加粗结构句
- 对开头五句额外加粗
- 在模板已明确时自由创新开头句式

## 输出合同

输出目录固定为：

- `_private/assets/07_润色成稿库/01_干货型成稿`

文件名固定为：

```text
选题_YYYY-MM-DD_HH-mm-ss.md
```

文件内部固定为：

1. H1：`选题_时间戳`
2. `文案结构：干货型`
3. `开头卡片编号：BKxxx`
4. 空行后直接进入最终成稿正文

最终成稿正文不输出表格，不输出模块来源清单，不输出旧三方案，不输出分析说明。

## 回写规则

生成成功后，回写手动输入选题表：

- `成稿时间=本次新时间戳`
- `成稿状态=已生成`

如果只是正文方案未生成，不允许先写成稿状态。

同样地，如果成稿审核未通过，也不允许把状态写成 `已生成`。

## 默认调用句

使用 `爆款开头成稿生成Skill`。读取 `_private/assets/04_爆款选题库/00_手动输入选题表.md` 中已完成正文方案的选题，先按 `文案结构` 路由到 `_private/assets/06_生成正文库` 找到该选题最新一版正文方案，再去 `_private/assets/05_爆款开头库` 按 `适合承载的论证方式` 和 `调用匹配规则` 选中最适合的 `BK` 卡片。最后在不改变开头结构和正文逻辑结构的前提下，把它们一起润色成笃定、口播化、口语化的最终成稿，并保存到 `_private/assets/07_润色成稿库/01_干货型成稿`，同时回写 `成稿时间` 和 `成稿状态=已生成`。
