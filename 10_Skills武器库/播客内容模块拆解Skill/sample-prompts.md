# 调用提示词示例

## 最简调用

```text
调用“播客内容模块拆解Skill”处理这个原始字幕，生成推荐理由、观点总览和完整观点类型文件夹。
```

## 完整调用

```text
请调用“播客内容模块拆解Skill”，完整读取我提供的原始字幕。

第一，生成 00-推荐理由.md，严格包含：
一句话推荐、为什么这篇内容值得听、为什么这个作者或嘉宾值得听、为什么现在值得听。
后三个板块各写3条。表达要激进、笃定、有压迫感，适合短视频传播。人物背书和最新时机需要联网核实，但不得编造身份、成就、数据和事件。

第二，不要按时间轴逐段复述，也不要再按单观点拆七模块。

请先判断整篇内容的总命题，再按原文真实推进建立若干主题板块。每个板块下面高密度提炼分支观点，每条分支观点先写成一句观点金句，然后在金句下面写 2 到 4 个结构化拓展点。

这些拓展点不要重复解释金句本身，要往下展开误区、步骤、判断、反常识点、关键动作、卡点或后果。
标签按观点内容自适应，不要求每条都一样，也不要求都必须写 3 点。
同时请把金句和拓展点写得更适合直接讲出来：短句优先，一句一个判断，尽量减少说明腔，可以有认知反差和轻微危机感，但不要喊口号、不要制造恐慌。

不要机械限定板块数量，但长播客默认按 20 到 30 条分支观点的密度去拆。高密度优先体现在“更敢拆独立判断”，不是重复拆同一个上位主题。

以原内容标题建立文件夹，生成 00-观点总览.md 和多个“编号 + 观点类型名”的文件。完成校验后直接保留完整文件夹。

不要只分析前半部分，不要遗漏重要类型，不要把背景、问题、案例和闲聊误判成观点。
```

## 强化观点类型拆解

```text
调用“播客内容模块拆解Skill”处理这篇内容。

不要机械套分类，也不要先看标题就下结论。先完整扫描全文，再建立观点候选池，最后按自然上位问题归成若干主题板块。板块数服从原文，不强凑；但分支观点要高密度拆开。不能把案例当观点，也不能把同一个判断重复拆好几条。

每条观点下面不要再写一整段“为什么”。请改成 2 到 4 个结构化点，优先写成“2个误区”“3个步骤”“3个判断”“2个反常识点”“4个关键动作”这类形式。
金句和下面这些点都要更像能直接开口讲的表达，不要写成说明文备注。
```

## 只处理某一类观点

```text
调用“播客内容模块拆解Skill”，生成整篇内容的推荐理由，但观点类型文件只保留和创业、AI、个人成长有关的类型。仍然先判断总命题，再在保留的类型下提炼分支观点，并生成观点总览。
```

## 在已有结果上重拆

```text
调用“播客内容模块拆解Skill”的新分类规则，重新扫描原文并覆盖当前输出文件夹。保留并重写 00-推荐理由.md，同时把旧的单观点文件结构改成“00-观点总览.md + 多个观点类型文件”。板块数尊重原文，但分支观点按高密度标准重拆。
```
