# 自建 IP 手绘视觉笔记图片 Skill

这是一个自包含的 skill，不再依赖 `xiaohu-ip-studio-main`。

职责分层：

- `ip-ppt-skill/scripts/build_ip_ppt.py`：文案分页（手动或自动）+ 页规格 + 16:9 整页图片归档 + Codex 出图清单

当前工作区目录分工固定为：

- `00_系统说明`：系统说明与迁移记录
- `10_Skills武器库\IP视觉PPT生成Skill`：skill 运行真源
- `02_资产中心\08_视觉配图库\01_干货型配图`：唯一正式成品归档根目录

skill 内部目录分工固定为：

- `outputs/<选题名>-work`：中间工作包，只放 `pages-spec.json`、`prompts/`、`codex-handoff.json`、`codex-workflow.txt`、`codex-render-job.json`、`codex-render-thread-prompt.md`
- `01_短视频PPT配图/<选题名>/`：唯一成品目录，只放 `page-xx.png`、`cover-3x4.png`、`cover-4x3.png`
- 如果当前平台不能在生成时直写正式目录，允许先生成到中间图片目录，再复制到正式目录，最后删除中间图片；最终仍只认成品目录

输入命中规则固定为：

- 选题主键只认文案第一行标题，不认输入文件名
- 如果原始 `.md` 路径不存在，但同标题工作包已经存在，可以直接按标题复用工作包
- 同标题存在多套工作包时，优先选择 `outputs/<选题名>（成稿）-work`，其次才是 `outputs/<选题名>-work`
- 复用现有工作包时，只回传清单与归档路径，不重新生成另一套工作包
- 每次准备工作包时，还会额外刷新 `codex-render-job.json` 和 `codex-render-thread-prompt.md`，供当前正式出图对话执行与阻塞说明使用

## 默认角色

当前默认角色是 `zhifuxingqiu-host`，基于：

- `refs/IP九宫格参考图.png` 对应的九宫格母版素材
- `refs/IP九宫格参考图.png` 对应的九宫格主定标板

角色固定识别点：

- 平顺、贴头皮、利落的背头侧分黑发
- 方框眼镜
- 中性偏暖、明显更深一点的自然肤色
- 主肤色基准固定为 `#e8a668`
- 白西装
- 黑内搭
- 现有 PPT 页里已经确认通过的手绘卡通小人风格，不走偏精修、偏写实的人像插画

正式主形象固定：

- 正式出图只允许平顺、贴头皮、利落的背头侧分主形象，不再允许自然前梳、没打发胶这类次级发型变体，也不允许卷感、波浪感、空气感、蓬感或高耸发顶

可变元素：

- 话筒
- 手势
- 姿态
- 表情
- 景别
- 站位
- 人物大小

## 使用前提

默认工作流直接走 Codex 生图，不需要额外 API 配置。

这套 skill 的正式执行方式只能是 Codex 直接按 `codex-handoff.json` 出图，不走额外 API Key 后端，不走外接 CLI 渲染器，不走 live 后端，不走兼容模型，不走另一条本地脚本执行器链路。

正式链路固定为：先读角色包与 `refs/IP九宫格参考图.png`，再按文案里的 `---` 分页，先生成 `pages-spec.json` 和逐页 prompt，最后由 Codex 按 `codex-handoff.json` 逐页出图。第 1 张图只对应第一个 `---` 之前的导语内容，后面的步骤总起句和 6 个误区必须留到后续页。若本次是整套完整出图，正文页完成后还会补两张独立封面图：`cover-3x4.png` 和 `cover-4x3.png`。

九宫格参考图的正式语义固定为：每次新文案正式出图前，模型都必须重新看到这张原图。只沿用上次会话记忆、只保留路径都不算通过；固定人物特征文字只允许做辅助稳定，不能替代原图。

默认角色必须使用 `zhifuxingqiu-host` 的九宫格定标板；固定人物特征文字只允许做辅助稳定，不允许只靠一句泛化的人物描述来出图。

角色锁定规则优先级最高：`text-only` 人物生成一律视为违规。如果执行环境不能把 `role_face_anchor_image` 作为真实参考输入带入生图链路，必须立刻中止并明确报错，不能继续靠 prompt 文案出图。

允许继续的前提只有一个：九宫格定标板已实际接入模型输入。不得使用真人锚点照、动作参考图、外部人物图或 API 侧身份参考。只看到参考图路径、只把参考要求写进文字 prompt、只抽取人物特征文字，或者无法确认九宫格参考图是否真的被模型使用，全部视为未通过角色锁定校验。

若当前执行环境无法真实挂载九宫格角色参考图，必须停止并汇报：`当前执行环境无法真实挂载九宫格角色参考图，本次停止生成，未进入正式出图链路。`

默认优先级是：九宫格主定标板作为唯一身份基准锁住人物画风、脸型、发型、肤色和眼镜，再由页面文案、场景结构字段和固定人物特征文字辅助稳定“这一页像不像同一个人、在做什么动作”。

默认允许更夸张的表情和动作，但脸型、发型、眼镜结构不能漂成另一个人。

肤色规则也固定：主肤色基准使用 `#e8a668`，允许极小范围的同色系明暗变化，但不允许整体漂白、偏粉、偏灰、偏冷或切回浅肤模板。

发型规则也固定：不是“只要往后梳就算对”，而是必须贴近九宫格里那种平顺、贴头皮、利落的背头侧分；只要出现卷发质感、波浪感、空气感、蓬感或明显抬高的发顶，都算锁人设失败，必须重做。

## 不要绕过链路

- 默认主流程是 `render-mode codex`
- 先生成 `pages-spec.json`、`prompts/`、`codex-handoff.json`
- 如果当前线程已经拿到本次生成所需的真实九宫格参考图输入，再按 handoff 逐页出图
- 正式模式下必须在当前这条出图对话里先拿到真实九宫格参考图输入；没有这一步，就不得开始正式出图
- handoff 里存在参考图路径，不等于已经完成参考图接入；正式出图前必须先验证九宫格参考图已在本次生成里真实挂载到模型输入
- 正式归档目录只认 `config/skill-config.json` 里的 `archive_root/<选题名>/...`；如果 `archive_root` 为空，不允许回退到 skill 相邻目录继续正式出图
- `<选题名>` 只允许来自文案第一行的选题标题，不允许回退到输入文件名；例如当前稿件必须落到 `02_资产中心\08_视觉配图库\01_干货型配图\不上班，一个人在家，到底怎样才能赚点小钱？`
- 如果输入文案第一行拿不到选题标题，脚本必须直接报错并停止，不创建正式归档子目录
- 不允许 live skill 和工作区副本各写一套结果，也不允许继续写入旧迁移目录或 `<旧Codex技能输出目录>`
- 最终页面图只认当前配置归档根目录下的 `\<选题名>\page-xx.png`
- 完整出图时，封面图还要写回当前配置归档根目录下的 `\<选题名>\cover-3x4.png` 和 `cover-4x3.png`
- 只要调用这个 skill 生成了图片，每一页都必须立刻写回 handoff 指定的 `output_image`
- 即使只是单独重做某页、单独重做某张封面，或单独生成某一张图片，也必须直接归档到该选题目录里的正式文件名
- 不要直接用临时手写 prompt 在别处出图后再倒回来冒充交付结果

## 快速使用

默认生成页面图时，不需要传 `--out`：

```bash
python scripts/build_ip_ppt.py \
  --input examples/minimal-explicit.txt
```

如果原始文稿路径不存在，但你已经有现成工作包，可以直接按标题回填：

```bash
python scripts/build_ip_ppt.py \
  --deck-title "不上班，一个人在家，到底怎样才能赚点小钱？" \
  --render-mode codex
```

## 运行模式

- 只允许 `codex`
  - 只生成分页规格和 prompt
- `codex`
  - 默认模式
  - 生成分页规格、prompt 和 Codex 出图清单
- 图片由 Codex 逐页生成后，优先直接保存或回写到 handoff 里的归档路径
- 如果当前平台只能先生成中间 PNG，再复制归档，也允许继续；但复制完成后必须删除中间 PNG
- 默认按单文件粒度清缓存：每一张图片复制并校验正式归档成功后，只删除这张对应缓存图，不默认清空整个 `generated_images` 目录
- 仅存在于临时生成目录、缓存目录、中间图片目录或对话附件里的图片不算完成
  - 每页 prompt 都要绑定当前页的角色参考姿态
- 默认最终交付只认页面图；完整出图时还会补两张封面图，不自动输出 PPT

输入文案格式：

```text
1
这是第一页正文
---
第一步
这是第二页正文
```

如果没有 `---`，系统会自动分页：

- 导语按语义切分
- 每一页如果写了 Markdown 加粗文字 `**...**`，该加粗文字优先直接作为这一页标题；只有该页没有加粗标题时，才回退到该页第一行或自动提炼标题
- `第一点 / 第二点 / 第三点` 这类步骤自动识别
- 不同步骤绝不放同一页
- 长步骤允许拆续页
- 第 1 张图只吃第一个 `---` 之前的内容
- 第 2 张图开始才进入步骤总起句和后续 6 个误区

角色构图补充规则：

- 第 1 页仍然是正文第 1 页，不单独改名为封面页；如果主题需要，可以做出更强的主视觉感
- 完整出图时，正文页全部完成后自动补两张独立封面：`cover-3x4.png` 和 `cover-4x3.png`
- 封面图不参与正文页码，也不替代第 1 页
- 封面图标题直接使用选题原文，不走正文页压缩逻辑
- 封面图背景固定使用和正文黄底同款的 `#fcb537`
- 封面图必须出现当前角色，而且动作、表情、姿态要直接服务选题含义
- 封面图人物约束必须和正文页完全一致：同一个角色 slug、同一张九宫格身份参考、同一套参考姿态库、同一条参考图路径体系
- 封面图不允许因为是封面就放宽人物锁定，不允许换脸、换发型、换眼镜、换衣着身份、换参考路径
- 封面图 `support_labels` 只允许少量原文短词或极少量英文短词做轻量点缀，但主标题仍然必须使用中文选题原文
- 封面点缀模块总数固定控制在 1 到 3 块之间，按可见辅助点缀块理解，不按单个词逐字计数
- 封面点缀模块把 `cue_phrases` 和 `support_labels` 放在同一个总量池里，合计最多 3 块
- 封面点缀模块只能做轻量辅助，不能扩成标签墙、批注云、环绕式说明区或多块密集说明区
- 封面图的人脸锁定至少与正文一致，并且在大主角封面场景下更严格优先遵守九宫格定标板的人脸身份
- 所有页面都必须以自己的主题为核心，人物只是配合主题，不是默认世界中心；正文页人物默认控制在 1 到 3 个之间
- 人物必须进入主结构内部，不能做画外独立主持人
- 人物必须和结构、标签、流程、道具发生直接动作关系，但只能承担辅助表达，不得作为整页主体替代物
- 后续页面不要一直居中，但也不能站在空白边上和主结构脱节
- 人物大小不是固定比例，但正文页默认以小点缀或中支撑为主，禁止用满页大主角把内容挤掉
- 允许半身特写和更近景的人物切法
- 允许人物缩小后嵌入某个关键词、小图标或步骤节点里做动作，但单页最多 3 个人物
- 全身图默认使用蓝色牛仔裤和小白鞋
- 动作要跟标题场景走，不要只是普通主持人站姿
- 动作可以更夸张，比如前倾、跨步、阻挡、指向、推进、顿悟
- 同一选题内，相邻页和近邻页不要复用近似动作、近似表情或近似主持姿态；如果主题接近，优先换动作簇和表情簇
- 同一页若出现多个同角色小人、不同景别或不同动作，也必须继续使用同一张九宫格参考锁定；若当前 Codex 直接生成环境做不到稳定锁定，必须先降为单主角色或单次校准，不允许硬出整页
- 每一页生成后，都必须回头对照主脸锚点图检查是不是同一个人；如果眼镜、肤色、发型、脸型、年龄感或白西装黑内搭不一致，只重做该页
- 配图和配字分开：配图只从原文显式内容和结构关系出发，不做延伸解释；配字只用原文短句和必要结构词，不允许扩写成解释段
- 配字规则改为“原文锚定 + 少量源自原文的结构词”，不是逐字死卡原文
- 默认正文版式不是极简信息图，而是“手写视觉笔记 + 小标签 + 小说明块 + 红色强调 + 结构配图”
- 小字标签是默认版式组成部分：正文页默认保留 2 到 5 个小标签或短说明元素，并允许 1 到 3 个短句式辅助说明，再围绕这些文字组织配图
- `cue_phrases` 负责最值得露出的原文短句，`flow_labels` 负责流程与方向词，`support_labels` 负责围绕结构的极短辅助标签
- 红色只允许做重点点缀，优先用于重点数字、结果词、关键箭头、警示点和强调型小标签
- 图片上禁止出现任何页码、页序、角标编号、`x/y` 计数，例如 `8/16`、`4/16`
- 但如果标题本身带有“第一点 / 第1步 / 第1条 / 认知一”这类引导数字，压缩标题时也必须保留在主标题里
- 人物可以更 Q 一些，但不能把白西装、黑色内搭、背头侧分、黑框眼镜、既定脸型画丢，也不能画成卫衣或陌生人
- `support_labels` 只允许做源自原文的极短结构说明，不允许做标签墙或大段解释
- `support_labels` 默认启用，不是可有可无的点缀；页面应先排标题、标签和短说明，再围绕这些文字做结构配图
- 长标题页允许压缩主标题，用 `display_title` 做主标题，用 `subtitle_notes` 承接原句剩余语义
- 如果同一段里同时出现两个步骤层级标记，例如“第二点 + 第一步”或“第二层 + 第一点”，第一个标记固定做主标题，第二个标记固定做副标题，后续内容句不得覆盖主副标题

场景与留白补充规则：

- 每页主标题先决定整页主场景
- 人物进入主场景里出演，不先摆一个固定主持人
- 标题本身也是画面构图的一部分，不使用固定标题条模板
- 标题位置和对齐方式默认随场景自动变化
- 左下角固定预留 13cm × 13cm 纯底色禁绘区域
- 左下角这块区域必须看起来只是背景自然延续，不画框、不画格、不画占位提示
- 左下角禁绘区域是硬性禁区，不允许人物、标题、图标、箭头、残影或任何装饰元素进入
- 该区域内不能放字、图标、人物、箭头和装饰线

图片归档规则：

- 所有页面图默认归档到配置项 `archive_root` 指向的目录；当前示例配置值是 `02_资产中心\08_视觉配图库\01_干货型配图`
- 每篇内容按选题自动新建一个同名文件夹
- `page-01.png` 这类页面图直接写入该选题文件夹
- 完整出图时，`cover-3x4.png` 和 `cover-4x3.png` 也直接写入该选题文件夹

```bash
  --input examples/7-mistakes-auto.txt \
```

```bash
  --assemble-only
```

正文图的文字规则：

- 主标题仍然保留，且必须按原文输出
- 如果主标题开头本身有“第一点 / 第1步 / 第1条 / 认知一”这类引导数字，主标题里必须保留，不允许压掉
- 额外可见文字以 `cue_phrases` 为主，只允许少量源自原文的 `support_labels`
- `cue_phrases` 仍以原文提炼为主
- `support_labels` 允许补少量极短结构说明词，但必须源自原文，不能变成长句、批注墙或满屏小字
- 封面图里的 `support_labels` 还允许少量英文短词，但必须和 `cue_phrases` 一起被压在 1 到 3 块封面点缀模块总量之内，不能变成英文长句或混合语言标签墙
- `visual_keywords` 和其他构图字段只用于场景规划，且必须源自原文，不作为可见文字来源
- 如果模型无法稳定写对小字，宁可少字，也不要生成错误字或自由补字
