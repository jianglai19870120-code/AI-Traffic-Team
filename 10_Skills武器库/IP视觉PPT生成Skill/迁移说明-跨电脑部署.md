# `ip-ppt-skill` 跨电脑迁移说明

这份说明只负责一件事：把同一套 skill、同一套角色资产、同一套出图链路，稳定迁移到另一台电脑。

## 1. 复制什么

跨电脑默认复制精简运行包，不复制历史输出和测试残留。

建议保留：

- `SKILL.md`
- `README.md`
- `调用说明-中文.md`
- `迁移说明-跨电脑部署.md`
- `scripts/`
- `config/`
- `characters/`
- `references/`
- `examples/`

不建议跟随迁移：

- `outputs/`
- `smoke-pages/`
- `smoke-test-work/`
- `work/`
- `test-auto.txt`
- `test-explicit.txt`
- `work-test-input.txt`
- `__pycache__` 等缓存产物

## 2. 新电脑放哪里

这套 skill 不强依赖固定盘符。

推荐当前这套目录结构：

1. 工作真源放在 `10_Skills武器库\IP视觉PPT生成Skill`
2. 正式成品根目录放在 `02_资产中心\08_视觉配图库\01_干货型配图`
3. 如需兼容 Codex 的已安装技能入口，可把 `%USERPROFILE%\.codex\skills\ip-ppt-skill` 做成指向工作真源的轻量入口或目录链接，而不是继续维护第二套副本

## 3. 归档目录怎么配

最终页面图和封面图的归档根目录来自 `config/skill-config.json` 里的 `archive_root`。

推荐做法：

1. 在新电脑上先确定你自己的归档根目录。
2. 把 `archive_root` 改成那台电脑的实际路径。
3. 文案第一行必须提供选题标题，正式归档子文件夹名只允许使用这个标题；如果缺标题，脚本必须停止。

这意味着新电脑不需要维持和旧电脑完全相同的盘符结构。

最终正式交付仍然只认：

- `当前 archive_root/<选题名>/page-xx.png`
- `当前 archive_root/<选题名>/cover-3x4.png`
- `当前 archive_root/<选题名>/cover-4x3.png`

其中 `<选题名>` 只允许使用文案第一行的选题标题，不允许回退到输入文件名。

## 4. 角色资产必须一起带走

跨电脑时，角色包不能只带一个 `character.md`。

至少要同时带走：

- `characters/zhifuxingqiu-host/character.md`
- `characters/zhifuxingqiu-host/refs/IP九宫格参考图.png`
- `characters/zhifuxingqiu-host/refs/reference-library.json`

页面图和封面图都依赖同一套角色链路，但人物身份只允许由九宫格定标板决定：

- 九宫格定标板：唯一人物身份基准，锁卡通脸型、发型、眼镜、肤色

“看得到文件路径”不算通过，“模型实际吃到了九宫格参考图”才算通过。

## 5. 最小验收

新电脑先跑一次最小验收，不要一开始就上正式选题。

推荐命令：

```bash
python scripts/build_ip_ppt.py \
  --input examples/minimal-explicit.txt \
  --render-mode codex
```

验收时确认：

1. 成功产出 `pages-spec.json`
2. 成功产出 `prompts/`
3. 成功产出 `codex-handoff.json`
4. 成功产出 `codex-workflow.txt`
5. `codex-handoff.json` 里的 `output_image` 指向当前配置归档根目录
6. 默认角色只引用 `IP九宫格参考图.png` 作为人物身份参考
7. 完整出图时，handoff 同时包含正文页和两张封面任务
8. 新电脑的 Codex 直接生成环境能够真实挂载九宫格参考图，而不是只消费文字 prompt

## 6. 日常运行口径

- 默认最终交付是 images-only
- 完整出图时会自动补两张封面图
- 单独重做某页或单独重做某张封面，也必须直接归档到正式文件名
- 只有用户明确要求 PPT 时，才额外传 `--out` 并运行 `--assemble-only`
- 正式执行统一走 Codex 直接按 `codex-handoff.json` 出图
- 如果新电脑上的 Codex 直接生成环境不能真实挂载九宫格参考图，必须停止，不能退回 text-only prompt，也不能改走别的 API/CLI/live/兼容模型后端

## 7. 三条不要改

- 不要直接用临时手写 prompt 代替 skill 链路
- 不要把临时目录、缓存目录或对话附件里的图当成正式交付结果
- 不要缺失角色参考资产后还期望人物一致性保持稳定
