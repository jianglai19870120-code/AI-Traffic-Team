# 自建 IP 手绘视觉笔记 PPT Skill

这个 skill 不做通用文章配图，也不做可编辑排版型 PPT。它只做一件事：

**把中文短视频文案生成成带固定 IP 角色出演的整页图片。**

默认执行方式也固定为一次性完整交付：

- 只要用户已经给出 `选题` 和 `文案` 或 `文案地址`，且没有明确要求“先只生成工作包 / 先只出几页 / 先只校准 / 分步执行”，就默认直接完成整套链路
- 默认完整链路包括：解析文案 -> 生成工作包 -> 按 `codex-handoff.json` 逐页出图 -> 生成 `cover-3x4.png` 和 `cover-4x3.png` -> 回写正式归档目录 -> 删除单张中间缓存图 -> 在确认正式目录成品齐全后删除本次工作包
- 默认最终交付物只认正式归档目录中的成品 PNG，不把工作包、缓存图、对话附件或临时目录当成交付结果
- 只有用户明确要求分开执行时，才允许停在“先做工作包”“先做前两页”“先看校准图”“先不清理过程文件”这类中间状态

## 适用场景

当用户表达这些意图时使用：

- “把这段文案做成 PPT”
- “按 --- 分页生成视觉笔记 PPT”
- “没有 --- 也帮我自动分页”
- “用我的 IP 做 PPT”
- “做成 NotebookLM 那种每页一张图的 PPT”

## 产出形态

- `pages/page-01.png` 这类逐页原图
- `cover-3x4.png`
- `cover-4x3.png`
- `pages-spec.json`
- `prompts/page-01.md` 这类逐页生图提示词
- `codex-handoff.json`
- `codex-workflow.txt`

当前工作区目录分工固定为：

- `00_系统说明`：系统说明与迁移记录
- `10_Skills武器库\IP视觉PPT生成Skill`：skill 运行真源
- `02_资产中心\08_视觉配图库\01_干货型配图`：唯一正式成品归档根目录

skill 内部目录分工固定为：

- `outputs/<选题名>-work`：中间工作包，只放 `pages-spec.json`、`prompts/`、`codex-handoff.json`、`codex-workflow.txt`、`codex-render-job.json`、`codex-render-thread-prompt.md`
- `01_短视频PPT配图/<选题名>/`：唯一成品目录，只放 `page-xx.png`、`cover-3x4.png`、`cover-4x3.png`
- 如果当前平台不能在生成时直接写正式目录，允许先生成到中间图片目录，再复制到正式目录，最后删除中间图片；最终只认成品目录

输入解析固定规则：

- 选题主键永远取文案第一行标题，不认输入文件名
- 如果给了 `--input` 但原始文稿路径不存在，只要给了 `--deck-title`，脚本会按标题回填现有工作包
- 同标题存在多套工作包时，优先命中 `outputs/<选题名>（成稿）-work`，其次才是 `outputs/<选题名>-work`
- 只要成功命中现有工作包，就直接复用其中的 `pages-spec.json`、`codex-handoff.json`、`codex-workflow.txt` 和 `prompts/`，不因缺少原始 `.md` 阻塞
- 每次生成或回填工作包后，还必须同步刷新 `codex-render-job.json` 和 `codex-render-thread-prompt.md`，用于当前正式出图对话的执行与阻塞说明

## 跨电脑迁移

- 默认只复制精简运行包：`SKILL.md`、`README.md`、`调用说明-中文.md`、`迁移说明-跨电脑部署.md`、`scripts/`、`config/`、`characters/`、`references/`、`examples/`
- `outputs/`、`smoke-pages/`、`smoke-test-work/`、`work/` 和历史测试文件不属于运行必需内容
- 新电脑只需要修改 `config/skill-config.json` 里的 `archive_root`，不需要维持完全相同盘符

## 固定规则

- 有 `---` 时严格按文案中的 `---`
- 没有 `---` 时自动按语义分页
- 每一页如果出现 Markdown 加粗文字 `**...**`，该加粗文字优先直接作为这一页标题；只有该页没有加粗标题时，才允许回退到第一页首行或自动提炼标题
- 自动分页时，不同步骤绝不放到同一页
- 每个步骤至少 1 页，长步骤允许拆成续页
- 第 1 张图只对应第一个 `---` 之前的导语内容，不把后面的步骤总起句和 6 个误区混进来
- 第 1 张图中的可见 IP 人物数量固定为 1，不允许出现 2 个或 3 个同角色人物分身
- 第 2 张图开始才进入步骤总起句、误区列表和后续分页
- 短标题页主标题默认按原文输出；长标题页允许压缩主标题并拆出小说明文字
- 如果原文标题里带有“第一点 / 第1步 / 第1条 / 认知一”这类引导数字，压缩标题时也必须保留在主标题里
- 页面可见文字原文锚定，只允许少量源自原文的结构词
- 页面可见配字必须直接从原文案中提取，不允许补写原文里没有出现过的新句子、新观点、新结论或新标签；允许做的只有原文摘取、原文短句压缩和原文结构词提取
- 配字约束写死：主标题、短句、`cue_phrases`、`flow_labels`、`support_labels`、`subtitle_notes` 都必须来自原文，不允许模型自行臆想文案；只有配图可以基于原文语义做适度拓展
- 默认页面表达模式改为 `graph-first / text-light / source-anchored`
- 正文页默认采用“主标题 + 极少量原文短句 + 图形结构主表达”的手写视觉笔记版式
- 正文页默认只保留 1 个主标题、1 到 2 条原文短句，并为每个主要小图、小节点、小误区卡片、小关系块配置 1 个极短结构标签；其余信息优先改成场景图、关系图、流程图、对比图和物体关系表达
- 禁止把页面做成解释型大字块、并列说明墙或多块文字框；凡是能用图表达的内容，不再额外补一句解释文字
- 小图标签默认控制在 2 到 6 个字，优先来自原文中的对象词、动作词、误区名、步骤名或结果词；必要时允许极轻微压缩，但不允许扩写成长解释
- 页面上禁止出现任何页码、页序、角标编号、`x/y` 计数，例如 `8/16`、`4/16`
- 配图和配字是两套逻辑：配图只从原文显式内容和结构关系出发，不做延伸解释；配字只用原文短句和必要结构词
- 默认角色必须走 `zhifuxingqiu-host` 的拆分参考链路；固定人物特征文字只允许做辅助稳定，不允许只靠一句泛化的人物描述来出图
- workspace 角色包必须实际包含 `refs/IP九宫格参考图.png`
- 九宫格母版文件是 `refs/IP九宫格参考图.png`，正式主脸锚点图是 `refs/ip-face-anchor-top-left.png`；如果任一文件不存在、路径改名，或参考库未指向它，先修正资源再出图
- 正式参考语义固定为：每次新文案正式出图前，模型都必须重新看到主脸锚点图 `refs/ip-face-anchor-top-left.png`；只沿用上次会话记忆、只保留路径都不算通过。固定人物特征文字只允许做辅助稳定，不能替代原图
- `codex` 模式下生成的每一页 prompt，必须把当前页对应的主脸锚点图路径、动作参考单图路径和动作文字提示写进 handoff
- 页面图和封面图都必须以主脸锚点图作为唯一人物身份基准：脸型、五官比例、发型、发际线、肤色、眼镜形态、年龄感都只能服从主脸锚点
- 默认主形象以 `refs/IP九宫格参考图.png` 为准，默认主发型固定为平顺、贴头皮、利落的背头侧分，不要画成卷毛、波浪感、空气感、蓬松卷发或高耸发顶
- 默认人物画风以已经确认通过的 PPT 页面小人风格为准，不要漂成偏精修、偏写实的人像插画
- 新的九宫格主定标板 `refs/IP九宫格参考图.png` 负责锁定人物画风、背头侧分、眼镜结构和更深两档的暖肤色
- 肤色以九宫格主定标板为准，使用中性偏暖、明显更深一点的自然肤色，不要画得过白
- 人物主肤色基准固定为 `#e8a668`
- 允许极小范围的同色系明暗变化，只用于正常手绘体积感；不允许整体漂白、偏粉、偏灰、偏冷或切回浅肤模板
- 正式出图只允许平顺、贴头皮、利落的背头侧分主形象，不再允许“自然前梳、没打发胶”这类次级发型变体，也不允许卷感、波浪感、空气感、蓬感或明显抬高的发顶
- 发型锁定强规则：如果结果虽然是背头方向，但仍出现卷曲发丝、波浪纹理、空气感、厚重蓬顶或明显高发顶，也视为人物锁定失败，必须重做
- 肤色锁定强规则：`#e8a668` 是默认主肤色基准，不允许改写为更白的商业插画肤色；若结果明显偏离该色系方向，也视为人物锁定失败，必须重做
- 人物可以更 Q 一些，但 Q 版只能改变夸张程度，不能改变白西装、黑色内搭、背头侧分、黑框眼镜、既定脸型和九宫格定标板锁定的身份识别点
- 禁止把人物画成卫衣、套头衫、便装外套或其他替代白西装的穿搭
- 单数页背景 `#fcb537`
- 双数页背景 `#122142`
- 单数页黑线，双数页白线
- 每页左下角禁止出现文字
- 每页至少 1 个头像人物，最多 3 个；人物只是辅助元素，不是整页主体替代物
- 话筒不是每页必出，只在讲述类页面按需出现
- 第 1 页仍然是正文第 1 页，不单独改名为封面页；如果主题需要，封面可以更强，但正文页仍先服从原文结构和辅助人物规则
- 第 1 页正文的人物数量上限强制收紧为 1；即使其他正文页允许 1 到 3 个辅助人物，第 1 页也只能保留 1 个 IP 人物
- 当本次是整套完整出图时，正文页全部完成后，还要补两张独立封面图：`cover-3x4.png` 和 `cover-4x3.png`
- 两张封面图都不算正文页，不参与页码，不替代第 1 页
- 封面图主标题直接使用选题原文，不走正文页压缩标题逻辑
- 封面图背景统一固定为和正文黄底同款的 `#fcb537`
- 封面图必须出现当前角色，且动作、表情、姿态必须服务选题含义
- 封面图人物约束必须和正文页完全一致：同一个角色 slug、同一张九宫格身份参考、同一条参考图路径体系
- 封面图不允许因为是封面就放宽人物锁定，不允许换脸、换发型、换眼镜、换衣着身份、换参考路径
- 封面图允许少量英文短标签来降噪，但主标题仍然必须使用中文选题原文
- 封面点缀模块总数必须控制在 1 到 3 块之间，按可见辅助点缀块理解，不是按单个字词计数
- 封面点缀模块把 `cue_phrases` 和 `support_labels` 视为同一个总量池，合计最多 3 块
- 封面点缀模块只能做辅助点缀，不能扩成标签墙、批注云、环绕式说明区或满屏小标签
- 封面图的人脸锁定至少与正文一致，并且在大主角封面场景下要更严格优先遵守九宫格定标板的人脸身份
- 所有页面都必须以自己的主题为核心，人物只是配合主题，不是默认世界中心；正文页人物默认控制在 1 到 3 个之间
- 后续页的人物站位、景别、大小都要主动变化
- 允许四种默认镜头层级：大主角、半身特写、小点缀人物、嵌入式小人物，但正文页默认不把人物做成满页主角
- 人物不必每页都做主体，可以嵌入某个关键词、某个步骤节点、某个图标小板块中执行动作
- 当页面主结构更重要时，优先让人物缩小并进入结构内部，而不是站在旁边当主持人
- 同一选题内，人物动作、表情、姿态提示必须结合当前页内容主动变化，不能连续几页都落成近似主持动作或近似情绪脸
- “避免重复”不只看连续两页，也看整套选题；允许同一情绪大类存在，但不能大面积变成几乎同构的演法
- 全身图时默认给蓝色牛仔裤和小白鞋
- 每页主标题先决定整页主场景
- 标题本身也是构图的一部分，位置与排法默认随场景自动变化
- 左下角固定预留 13cm × 13cm 纯底色禁绘区域
- 左下角这块区域只保留自然连续的背景，不画框、不画格、不画占位提示
- 左下角禁绘区域是硬性禁区，任何文字、人物、图标、箭头、线条、残影都不能进入
- 所有页面图默认归档到配置项 `archive_root` 指向的目录；当前示例配置值是 `02_资产中心\08_视觉配图库\01_干货型配图`
- 归档子文件夹名只允许使用文案第一行的选题标题；例如标题是“不上班，一个人在家，到底怎样才能赚点小钱？”，正式目录就必须是 `02_资产中心\08_视觉配图库\01_干货型配图\不上班，一个人在家，到底怎样才能赚点小钱？`
- 如果缺少选题标题，必须直接停止并报错；不允许回退到输入文件名、成稿文件名或手动自定义目录名
- 不允许 live skill 和工作区副本各写一套结果，也不允许继续写入旧迁移目录或 `<旧Codex技能输出目录>`
- 若 `archive_root` 为空，必须先停止并修正配置，不允许回退到 skill 相邻目录继续正式出图

## 硬性执行规则

- 角色锁定规则优先级最高；`text-only` 人物生成一律视为违规
- 如果执行环境不能把 `role_face_anchor_image` 作为真实参考输入带入生图链路，必须立刻中止并明确报错，不能继续靠 prompt 文案出图
- 允许继续的前提只有一个：九宫格定标板已实际接入模型输入；不允许使用真人锚点照、动作参考图、外部人物图或 API 侧身份参考
- 只看到参考图路径、只把参考要求写进文字 prompt、只抽取人物特征文字，或者无法确认九宫格参考图是否真的被模型使用，全部视为未通过角色锁定校验
- 若当前执行环境无法真实挂载九宫格角色参考图，必须停止并汇报：`当前执行环境无法真实挂载九宫格角色参考图，本次停止生成，未进入正式出图链路。`
- 禁止直接用临时手写 prompt 绕过 skill 链路出图
- 任何页面或封面里的可见配字，如果不能明确回指到原文句子、原文短语或原文结构词，一律视为违规结果，必须重做
- 必须先运行 `build_ip_ppt.py` 产出 `pages-spec.json`、`prompts/`、`codex-handoff.json`
- `codex` 模式下，逐页出图必须以 `codex-handoff.json` 为唯一执行清单
- `codex` 模式下，正式链路只认“当前正式出图对话已真实看到主脸锚点图，并按页可选带 1 张动作参考单图”；`codex-render-job.json` 和 `codex-render-thread-prompt.md` 只负责说明当前对话怎么执行、怎么阻塞、怎么验收
- 即使未来自动附图能力打通，也必须保留“每页生成后对照九宫格验脸”的步骤；如果眼镜、肤色、发型、脸型、年龄感或白西装黑内搭不一致，只重做该页
- handoff 里的 `output_image` 是唯一最终交付路径；如果先生成了中间图片，也必须复制到这个路径后再删除中间图片，不能把缓存图或中间图当成交付结果
- 最终页面图只认当前配置归档根目录下的 `\<选题名>\page-xx.png`
- 完整出图时，两张封面也必须直接写回当前配置归档根目录下的 `\<选题名>\cover-3x4.png` 和 `cover-4x3.png`
- 只要调用这个 skill 生成了图片，每一页都必须立刻写回 handoff 指定的 `output_image`；只停留在临时目录、缓存目录或对话附件里的图片不算完成
- 如果当前平台只能先生成中间 PNG，再复制归档，也允许继续；但复制完成后必须删除中间图片，只保留正式归档目录中的成品
- 默认按单文件粒度清缓存：每一张图片复制并校验正式归档成功后，只删除这张对应缓存图；不默认清空整包 `generated_images` 缓存目录
- 即使只是单独重做某页、单独重做某张封面，或单独生成某一张图片，也必须直接归档到该选题目录里的正式文件名，不能只停留在 `generated_images`、临时目录或对话附件里
- 如果只是想校准风格，也要先走 handoff，再从 handoff 指定页码逐页出图
- 出图线程结束后，必须再按 `scripts/verify_codex_render_job.py` 或 `codex-render-job.json` 中的 expected_outputs 核对正式目录文件是否齐全
- 红色只允许做重点点缀，优先用于重点数字、结果词、关键箭头、警示点和强调型小标签
- 小字标签是小图讲解锚点，不是长解释文本；页面含义必须主要由图形结构、场景关系和人物动作关系完成，同时每个主要小图都要有可指认的短标签

## 首次使用前

### 1. 默认走 Codex 生图

默认工作流不需要也不允许配置任何额外 API。

- 正式链路固定为：读取 `SKILL.md` -> 读取 `characters/zhifuxingqiu-host/character.md` -> 读取 `refs/IP九宫格参考图.png` -> 按 `---` 分页 -> 生成每页 prompt -> 由 Codex 按 handoff 逐页出图

## 正常生成流程

1. 读取用户文案
2. 用文案第一行提取选题标题，并把它作为唯一合法的归档子文件夹名
3. 有 `---` 就按手动分页；没有 `---` 就自动切页
4. 读取默认角色，默认就是 `zhifuxingqiu-host`
5. 读取该角色的九宫格参考图，确认 `refs/IP九宫格参考图.png` 是唯一人物参考输入
6. 解析每页标题、正文、页型
7. 解析每页人物大小、站位、景别、镜头层级和场景动作
8. 判断该页人物是做大主体、半身特写、小点缀还是嵌入式小人物
9. 为每页生成 prompt 文件，并把九宫格参考图路径和当前页动作文字提示写入 handoff
10. 根据模式选择图片来源：
   - `codex`：先生成 handoff，再由 Codex 按 handoff 逐页出图
11. 不管底层怎么出图，最终页面图都必须保存或回写到 handoff 里的归档路径
12. 如果本次是完整出图，正文页全部完成后，再补 `cover-3x4.png` 和 `cover-4x3.png`
13. 所有成品图归档完成后，必须核对正式目录中的目标文件是否齐全
14. 如果归档文件已经齐全，必须删除单张中间缓存图，并继续删除本次 `outputs/<选题名>-work` 工作包，不要求用户再补“下一步”
15. 默认只保留页面图和封面图归档，不再做 PPT 装配
16. 只有用户明确要求时，才额外装配 PPT

## 生成命令

默认生成页面图时，不需要传 `--out`：

```bash
python scripts/build_ip_ppt.py \

```

可选切换角色：

```bash
python scripts/build_ip_ppt.py \
```

如果要走 Codex 直接出图：

```bash
python scripts/build_ip_ppt.py \
```

如果原始文稿路径已经失效，但同标题工作包还在，可以直接按标题回填：

```bash
  --render-mode codex \
  --pages 1-2,5
```

## 自动分页规则

- `---` 是最高优先级；只要输入里有 `---`，系统绝不自作主张重分
- 没有 `---` 时，系统会先识别导语、步骤块和尾声
- 手动分页时，如果某一页写了 `**加粗标题**`，这一页就直接用该加粗文字做标题；没有加粗标题时，才回退到该页第一行或自动提炼
- `第一点 / 第二点 / 第三点` 这类步骤是硬边界
- 不同步骤绝不混页
- 每个步骤至少一页
- 如果某个步骤太长，会拆成该步骤的续页
- 续页标题会自动总结，例如 `第一点｜能力要能脱离岗位独立成立`
- 导语部分允许按语义拆成 1 页或多页，但不能跨进 `第一点`

## Codex 出图模式

- `render-mode codex` 不调用外部图像 API
- 它会产出：
  - `pages-spec.json`
  - `prompts/page-XX.md`
  - 完整出图时额外产出 `prompts/cover-3x4.md` 和 `prompts/cover-4x3.md`
  - `codex-handoff.json`
  - `codex-workflow.txt`
  - `codex-render-job.json`
  - `codex-render-thread-prompt.md`
- 然后由 Codex 读取 handoff；正式模式下要求当前这条出图对话先真实看到主脸锚点图，并按页带上 handoff 指定的动作参考单图，再按选定页码逐页生成图片并写回正式目录
- 如果这次是完整出图，正文页全部写回后，还要继续生成 `cover-3x4.png` 和 `cover-4x3.png`
- handoff 里的 `output_image` 是唯一最终交付路径；缓存路径只能当中间态
- 即使只是单独生成或单独重做某张封面，最终也必须写回该封面的归档目标路径，不能只保留临时生成图
- handoff 里的 `display_title`、`cue_phrases` 是主文字来源，只允许少量源自原文的 `support_labels` 和 `subtitle_notes` 做结构说明
- handoff 里的角色参考必须写出 `role_face_anchor_image`、`role_action_reference_image`、`role_action_reference_reason` 和 `role_reference_strategy = anchor-plus-pose`
- 不允许额外改走 API Key 后端、外接 CLI 渲染器、兼容模型、live 后端或另一条本地脚本执行器链路来替代 Codex 直接生成
- 封面 `support_labels` 允许混入少量英文短词，但只能做结构点缀，不能变成英文长句或混合语言标签墙
- `cover_outputs` 和封面 handoff 还必须写出 `cover_accent_blocks_min`、`cover_accent_blocks_max`，并按 1 到 3 块控制封面点缀总量
- 如果原始标题里带有引导数字，`display_title` 必须保留这段数字型引导
- 不允许脱离 handoff 另起一套临时 prompt 直接出图
- 默认最终交付认页面图；完整出图时还认两张封面图；只有用户明确要 PPT 时，才运行 `--assemble-only` 重新装配
- 如果某一页效果不满意，只需要重新跑对应页码，不必整套重来

- 生图统一走 16:9

- `pages-spec.json` 必须写出 `title_text`、`display_title`、`cue_phrases`
- `pages-spec.json` 必须把配图字段和配字字段分开：

  - 配字字段：`title_text`、`display_title`、`cue_phrases`、`flow_labels`、`support_labels`、`subtitle_notes`

- `pages-spec.json` 在双层步骤页里还必须明确主标题和副标题语义：第一个步骤标记做主标题，第二个步骤标记进 `subtitle_notes`
- `pages-spec.json` 还必须写出 `role_scale`、`role_position`、`role_framing`、`role_composition_mode`

- 失败时明确指出是角色缺失、分页为空、目标归档图片未写回，还是 PPT 装配失败

## 人物入场硬规则

- 人物必须进入当前页主场景内部，不能做画外独立主持人
- 人物必须和至少一个主结构元素发生直接动作关系
- 人物允许更 Q 版，但不允许变装、变发型、变眼镜、变脸型、变成陌生人
- 动作关系包括但不限于：
  - 触碰标签
  - 操作道具
  - 跨越流程节点
  - 站进对比结构中间
  - 被结构包围、限制或推动
- 如果主结构已经很满，优先缩小人物并嵌入结构，不要把人物独立摆在侧边
- 结构页、误区页、流程页优先让结构成为视觉中心，人物只承担嵌入式动作表达
- 如果页面出现“设计 / 写作 / 判断 / 推进 / 拆解”这类局部结构，允许人物以小人物方式直接嵌进对应结构里演动作
- 同一选题内，相邻页和近邻页不得同时出现高度相近的动作语义、表情语义，或“相同景别 + 相同站位 + 相同演法”组合
- 如果当前页和近邻页主题相近，优先切换动作簇、表情簇、姿态提示和嵌入方式，而不是继续复用上一页的主持姿态

## 文字与长标题规则

- 页面可见文字不再要求只能逐字来自原文
- 页面可见配字必须来自原文；这里的“原文锚定”不是允许自由改写，而是要求所有可见文字都能在原文里找到出处
- 主原则改为：配字严格取自原文，配图允许基于原文做适度拓展
- `cue_phrases` 仍以原文提炼为主
- `support_labels` 默认启用，作为围绕页面结构的极短辅助字块；必须源自原文，不用于解释对照、流程、结果链路之外的新含义
- 不允许为了让页面“更完整”而额外发明提示语、总结句、结果句、警示语或标签词；凡是页面上能看见的字，都必须能回溯到原文
- 这些结构词只服务原文勾画，不允许变成长段说明、标签墙或满屏文字
- `flow_labels` 负责流程、步骤和方向词；`cue_phrases` 负责最值得露出的原文短句；`support_labels` 负责围绕结构的极短辅助标签
- 长标题页允许 `display_title_mode = compressed`
- 长标题页默认用短主标题 `display_title`，并用 `subtitle_notes` 承接原句剩余信息
- 但如果标题开头自带“第一点 / 第1步 / 第1条 / 认知一”这类引导数字，`display_title` 必须保留这段前缀，不允许压掉
- 如果同一段里同时出现两个步骤层级标记，例如“第二点 + 第一步”或“第二层 + 第一点”，第一个标记固定做主标题，第二个标记固定做副标题，后面的内容句不得抢占标题位
- 短标题页默认 `display_title_mode = exact`
