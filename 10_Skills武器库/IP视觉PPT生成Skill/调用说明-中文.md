# `ip-ppt-skill` 中文调用说明

这套 skill 现在默认走 `Codex` 生图。

如果你要我直接帮你生成这组图，**通常只需要给我两样东西**：

1. `选题`
2. `正文文案`

只要你已经把这两样给全，而且没有特别说明要“分步来”，我现在会默认一次性做完：

- 自动生成工作包
- 自动逐页出图
- 自动补两张封面
- 自动归档到正确的正式目录
- 自动删除单张缓存图
- 自动删除本次工作包过程文件

也就是说，正常情况下你不需要再补“下一步”“继续”“把剩下的也做完”这类提醒。

默认图文表达也已经切成：

- `graph-first`：优先用场景图、关系图、流程图、对比图表达
- `text-light`：每页只保留少量原文短句
- `source-anchored`：文字来源继续锚定原文，但不再把整页信息都写出来
- 正文页里每个主要小图、小节点、小误区块、小流程块，都必须带一个极短标签，方便边讲边指

如果你已经用 `---` 手动分好了页，我会严格按 `---` 切页。  
如果你没有加 `---`，我会按语义自动分页。
如果某一页里已经写了 Markdown 加粗文字 `**...**`，我会直接把这段加粗文字当成该页标题；只有没加粗时，才帮你提炼标题。

跨电脑迁移时，默认只复制精简运行包：`SKILL.md`、`README.md`、`调用说明-中文.md`、`迁移说明-跨电脑部署.md`、`scripts/`、`config/`、`characters/`、`references/`、`examples/`。

如果原始成稿文件后面挪走了，也不会直接卡死。现在默认规则是：

- 先按 `选题` 匹配现有 work package
- 同标题存在多套时，优先复用 `outputs/<选题名>（成稿）-work`
- 找不到 `（成稿）-work` 时，再回退到 `outputs/<选题名>-work`
- 最终图片仍然只写到 `01_短视频PPT配图/<选题名>/`
- 工作包里现在还会固定多出两个执行说明文件：`codex-render-job.json` 和 `codex-render-thread-prompt.md`
- 出图完成后，可以直接用 `scripts/verify_codex_render_job.py` 按工作包核对 13 张 PNG 是否都已经写回正式目录
- 如果当前平台不能在生成时直写正式目录，允许先生成到中间图片目录，再复制到正式目录，最后删除中间图片；最终仍只认正式目录
- 默认按单文件粒度清缓存：每一张图片复制并校验正式归档成功后，只删除这张对应缓存图，不默认清空整个 `generated_images` 目录

## 最简调用方式

直接把下面这段话发给我，把里面的内容替换成你的选题和文案就可以：

```text

4. 人物必须进入主场景内部，和结构、标签、流程、道具发生直接动作关系，不要做画外独立主持人，也不要用大量重复人物替代内容
5. 左下角 13cm × 13cm 必须保留纯底色禁绘区域，只保留背景自然延续，不画框、不画格、不画占位提示

10.3 小图标签优先来自原文中的对象词、动作词、误区名、步骤名和结果词，默认控制在 2 到 6 个字，不允许写成长解释
11. 第 1 张图只对应第一个 `---` 之前的导语，不把后面的步骤总起句和 6 个误区混进来
12. 默认角色必须用 `zhifuxingqiu-host` 的九宫格定标板；固定人物特征文字只做辅助稳定，不要用泛化人物

15. 人物主肤色基准固定为 `#e8a668`，允许极小范围的同色系明暗变化，但不允许整体漂白、偏粉、偏灰、偏冷或切回浅肤模板；若明显偏离该色系方向，视为锁人设失败
16. 允许更夸张的表情和动作，也允许半身特写、小点缀人物、嵌入式小人物，但正文页默认最多 3 个
17. 如果标题里有“第一点 / 第1步 / 第1条 / 认知一”这类引导数字，主标题里必须保留，不能因为压缩标题被删掉

20. 封面人物约束必须和正文页完全一致：同一个角色 slug、同一张九宫格身份参考、同一条参考图路径体系
21. 封面辅助标签允许少量英文短词来降噪，但主标题仍然必须是中文选题原文

24. 封面点缀模块只能做轻量辅助，不能扩成标签墙、批注云、环绕式说明区或多块密集说明区
25. 红色只允许做重点点缀，优先用于重点数字、结果词、关键箭头、警示点和强调型小标签

27. 只有当九宫格定标板已在本次生成里实际接入模型输入时，才允许继续生成；不允许使用真人锚点照、动作参考图、外部人物图或 API 侧身份参考。固定人物特征文字只做辅助稳定，不能替代原图接入

选题：这里写你的选题

文案：
```

## 我会默认执行的规则

- 默认角色：`zhifuxingqiu-host`
- 默认风格：现有 IP 手绘视觉笔记风格
- 默认正文版式：图像优先、少字锚定的视觉笔记页，不走满屏文字块，也不走极简海报
- 默认模式：`render-mode codex`
- 唯一正式出图链路：`codex-handoff.json`
- 默认归档根目录从 `config/skill-config.json` 里的 `archive_root` 读取；当前示例配置值是 `02_资产中心\08_视觉库\01_干货型视觉`
- `outputs/<选题名>-work` 永远作为中间工作包目录，只放 `pages-spec.json`、`prompts/`、`codex-handoff.json`、`codex-workflow.txt`
- `outputs/<选题名>-work` 里的 `codex-render-job.json` 和 `codex-render-thread-prompt.md` 用于说明当前正式出图对话怎么执行、怎么阻塞、怎么验收
- `01_短视频PPT配图/<选题名>/` 永远作为唯一成品目录，只放 `page-xx.png`、`cover-3x4.png`、`cover-4x3.png`
- 归档子文件夹名只允许使用文案第一行的选题标题；不允许回退到输入文件名或成稿文件名
- 有 `---` 时严格按 `---` 分页
- 没有 `---` 时自动语义分页
- 不同步骤绝不混页
- 所有页面都按“主题优先，人物配合主题”来构图
- 人物必须进入当前页主结构内部，不做画外独立主持人
- 页面可见文字原文锚定，只允许少量源自原文的结构词
- `cue_phrases` 默认承担最值得露出的原文短句，`flow_labels` 承担流程和方向词，`support_labels` 承担围绕结构的极短辅助标签
- `support_labels` 改成正文页的小图标签主通道；页面含义优先由图形结构、场景关系和人物动作关系完成，但每个主要小图都应有短标签锚点
- 如果同一段里同时出现两个步骤层级标记，例如“第二点 + 第一步”或“第二层 + 第一点”，第一个标记固定做主标题，第二个标记固定做副标题
- 如果标题本身带有“第一点 / 第1步 / 第1条 / 认知一”这类引导数字，主标题里必须保留
- 长标题页默认允许压缩主标题，并用较小说明文字承接原句剩余语义
- 最终图片只认归档目录，不以缓存路径或中间图片目录交付
- 即使只是单独重做某页、单独重做某张封面，或单独生成某一张图片，也必须直接归档到该选题目录里的正式文件名
- 如果第一行不是合法选题标题，必须直接停止并报错，不创建正式归档目录
- 默认最终交付只要图片，不自动输出 PPT
- `text-only` 人物生成一律视为违规；如果执行环境不能把 `role_face_anchor_image` 作为真实参考输入带入生图链路，必须立刻中止并明确报错
- 允许继续的前提只有一个：九宫格定标板已实际接入模型输入；不允许使用真人锚点照、动作参考图、外部人物图或 API 侧身份参考
- 只看到参考图路径、只把参考要求写进文字 prompt，或者无法确认九宫格参考图是否真的被模型使用，全部视为未通过角色锁定校验；固定人物特征文字不能单独作为放行条件
- 失败出口固定为：`当前执行环境无法真实挂载九宫格角色参考图，本次停止生成，未进入正式出图链路。`
- 如果本次是整套完整出图，正文页完成后自动补两张封面图
- 两张封面都用选题做主标题，背景固定为 `#fcb537`
- 两张封面都必须复用正文页同一张九宫格身份参考，不允许切到另一套脸或另一条参考图路径
- 封面 `support_labels` 允许少量英文短词，但必须和 `cue_phrases` 一起被压在 1 到 3 块封面点缀模块总量之内
- 封面点缀模块总数固定控制在 1 到 3 块之间，不能扩成标签墙、批注云、环绕式说明区或多块密集说明区
- 封面的人脸锁定至少与正文一致，并且在大主角封面场景下更严格优先遵守九宫格定标板的人脸身份
- 人物主肤色基准固定为 `#e8a668`
- 发型必须是九宫格里那种平顺、贴头皮、利落的背头侧分；如果虽然往后梳了，但仍有卷感、波浪感、空气感、蓬感或高发顶，也视为失败
- 红色只允许做重点点缀，优先用于重点数字、结果词、关键箭头、警示点和强调型小标签
- 只要调用这个 skill 生成了图片，每一页都必须最终归档到 handoff 指定的 `output_image`；若先生成中间 PNG，复制后必须删除中间图片
- 左下角只保留纯背景，不画框、不画格、不画占位提示
- 配图只从原文显式内容和结构关系出发，不做延伸解释；配字以原文短句和必要结构词为主
- 如果 `archive_root` 为空且会触发 skill 相邻目录回退，必须先停止并修正配置，不允许边出图边临时分流到另一套目录
- 不允许继续写入 `<旧Codex技能输出目录>` 或任何旧迁移目录；唯一正式归档目录只认 `02_资产中心\08_视觉库\01_干货型视觉`
- 当前正式命名规则是 `02_资产中心\08_视觉库\01_干货型视觉\<选题标题>\...`，其中 `<选题标题>` 只允许来自文案第一行

## 什么时候还需要额外说明

只有下面这些情况，才建议你额外补一句：

- 你想指定某几页重做
- 你想换角色
- 你想把文案压得更短
- 你只想单独做封面，不想跑正文页

如果没有这些特殊需求，**你以后直接给我选题和文案就够了**。

- 先读取 `SKILL.md` 和 `characters/zhifuxingqiu-host/` 里的角色包

- 再按 `---` 切页
- 第 1 张图只对应第一个 `---` 之前的导语
- 后续页才进入 6 个误区
- 每页都必须绑定对应的角色参考姿态，不允许只用泛化人物描述
- 参考图存在于 handoff 或本地磁盘，不等于已经完成参考图接入；正式出图前必须先验证九宫格参考图已真实挂载到模型输入

- 如果本次是整套完整出图，正文页全部完成后还要补 `cover-3x4.png` 和 `cover-4x3.png`
- 默认主发型是平顺、贴头皮、利落的背头侧分，肤色中性偏暖且略深一点
- 默认只参考 `refs/IP九宫格参考图.png` 作为唯一身份基准锁定小人画风、脸型、发型和肤色；动作由文案和页面结构字段决定；固定人物特征文字只做辅助稳定
- 正式出图只允许背头侧分主形象，不再允许“自然前梳”这类次级发型
- 封面也必须走同一套角色链路：同一个角色 slug、同一张九宫格身份参考、同一条参考图路径体系
- 封面点缀模块总数固定控制在 1 到 3 块之间，`cue_phrases` 和 `support_labels` 合计最多 3 块
- 封面点缀模块只能做轻量辅助，不能扩成标签墙、批注云、环绕式说明区或多块密集说明区
- 人物主肤色基准固定为 `#e8a668`，允许极小范围的同色系明暗变化，但不允许整体调整肤色方向
- 人物允许以大主角、半身特写、小点缀或嵌入式小人物四种方式出现，但正文页默认最多 3 个
- 人物可以更 Q 一些，但不能把白西装、黑色内搭、背头侧分、黑框眼镜、既定脸型画丢，也不能画成卫衣或陌生人
- 同一页若出现多个同角色小人、不同景别或不同动作，也必须继续使用同一张九宫格参考锁定；若当前执行端做不到稳定锁定，必须先降为单主角色或单次校准，不允许硬出整页

## 稳定生成默认做法

- 默认先跑 `build_ip_ppt.py`
- 先生成 `pages-spec.json`、`prompts/`、`codex-handoff.json`
- 再按 `codex-handoff.json` 逐页出图
- 出图前先做“参考图接入校验”；若当前工具只支持文字 prompt、不支持真实参考图输入，必须停止并汇报，不允许先出图再人工挑像的一张
- 最终图片必须回写到当前配置归档根目录下的 `\<选题名>\page-xx.png`；当前正式目录固定为 `02_资产中心\08_视觉库\01_干货型视觉`
- `<选题名>` 只允许使用文案第一行标题清洗后的结果；例如当前稿件必须写回 `02_资产中心\08_视觉库\01_干货型视觉\不上班，一个人在家，到底怎样才能赚点小钱？`
- 完整出图时，两张封面也必须回写到同目录下的 `cover-3x4.png` 和 `cover-4x3.png`
- 即使只是单独生成或单独重做某张封面，也必须直接写回这个选题目录里的正式封面文件名
- 不要直接写一段临时 prompt 在别处出图，再把缓存图拿来当正式结果
- 先做 1-2 页校准风格，再放量做整套
- 仅存在于临时生成目录、缓存目录、中间图片目录或对话附件里的图片不算完成
- 图片上不要出现任何页码、页序、角标编号、`x/y` 计数，例如 `8/16`、`4/16`
- 只要用户已经给出 `选题 + 文案或文案地址`，且没有明确要求分步执行，就默认直接跑完整链路：工作包 -> 正文页 -> 两张封面 -> 正式归档 -> 清理过程文件
- 默认不要求用户在工作包生成后再补“下一步”；除非用户明确要求“先停在某一步”
