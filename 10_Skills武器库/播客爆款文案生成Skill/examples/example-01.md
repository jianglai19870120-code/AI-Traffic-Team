# 示例调用

```text
调用“播客爆款文案生成Skill”。

BK开头卡片：
<BK卡片绝对路径>

B播客原稿：
<播客原文绝对路径>

播客拆解目录：
<播客拆解目录绝对路径>

这次生成6条观点。

如果B还没有对应的播客拆解结果，就先调用“播客内容模块拆解Skill”补齐。

开头按BK001的五句结构骨架和调用匹配规则来写，但不要照抄A文案的具体人物、公司、数字和原句。
同时开头要强模仿A的句长、停顿、长短句交替和口语推进。
每个开头结构位优先只落1句或半句，不要把连续短句写成长解释。

正文只允许使用这篇B播客拆解结果中的前6条观点，按原顺序整理成完整口播整稿。
输出目录：
<输出目录绝对路径>

请先输出爆款开头复刻，再输出三条主线方案，并让开头和观点都能对回上游来源。
```

## 预期输出特征

- 只生成一个 Markdown 文件；
- 文件位于用户指定的输出目录；
- 文件名为 `YYYYMMDD_HHMM_短视频标题.md`；
- 文件前部有一张爆款开头复刻表；
- 开头有明显的对标结构影子；
- 开头能看出短句、停顿和推进感；
- 三条主线使用的观点都来自同一篇 B 播客的内容模块拆解结果；
- 每条主线只有一句主线和一张四列表；
- 选用观点保留完整观点内容，对应来源只保留一个可追溯链接。
