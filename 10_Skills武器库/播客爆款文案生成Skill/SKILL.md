# 播客爆款文案生成Skill

## 何时调用

当用户已经同时提供下面 3 个要素时，才允许调用本 Skill：

1. 一份要复刻的 `B` 播客原稿  
   常见位置：`01_热门播客/01_播客文稿/...`
2. 一份要学习并复刻的爆款开头卡片文件  
   常见位置：`02_资产中心/05_爆款开头库/BK...md`
3. 一个明确的观点数量  
   常见值：`3`、`6`、`8`、`10`

如果这 3 个要素里任何一项缺失，都必须停止，不允许自行猜测或先生成一部分。

这里的第 2 项必须是 `02_资产中心/05_爆款开头库` 下的正式开头卡片文件。

明确禁止把下面这类文件当成结构输入：

- 任何只有对标视频全文、但还没有拆成正式开头卡片文件的原文稿

## 缺项时的固定提醒

当输入不完整时，固定提示：

```text
当前还不能开始生成。

还缺少以下必要输入：
- B播客原文：是否已提供
- BK 开头卡片：是否已提供
- 观点数量：是否已提供

请补齐这三个要素后，我再继续调用这个 skill。
```

如果用户给的是对标视频原文，而不是 `BK` 爆款开头卡片文件，固定提示：

```text
当前还不能开始生成。

你提供的是对标视频原文，不是 BK 开头卡片。
请改为提供 `02_资产中心/05_爆款开头库/` 下面的 `BK...md` 文件后，我再继续。
```

## 这个 Skill 负责什么

- 读取指定的 `BK` 爆款开头卡片文件；
- 读取指定的 `B` 播客原稿；
- 根据这篇 `B` 播客原稿，去定位 `01_热门播客/02_播客拆解` 下对应的拆解目录；
- 只读取该拆解目录下已经存在的 `00-推荐理由.md`、`00-观点总览.md` 和多个观点文件；
- 先充分学习开头卡片里的原文前5句、逐句拆解、五句推进逻辑、五句结构骨架和调用匹配规则；
- 输出一张只负责开头的 `爆款开头复刻` 表；
- 再输出 3 条 `主线方案`；
- 每条主线只保留一句主线 + 一张四列表；
- `选用观点` 直接输出观点原句和它下面的结构化条目，而不只是观点标题；
- `对应来源` 单独一列只输出一个 Obsidian 可点击来源链接；
- 只把结果保存到 `03_爆款文案/01_生成文案`。

本 Skill 不负责：

- 重新拆解 A 对标视频开头；
- 重新设计爆款结构本身；
- 接收对标视频原文并临时重新拆结构；
- 读取 `B` 播客原文后再重新拆一遍观点；
- 跨播客混用观点；
- 生成旧版“入选观点清单 + 正文结构映射总表”；
- 直接把结果写入 `03_爆款文案/02_成稿文案`。

## B 播客原稿的用途

这里的 `B播客原稿` 只承担一个作用：

- 用来定位这篇播客在 `01_热门播客/02_播客拆解` 下对应的是哪一个拆解目录

定位到拆解目录之后：

- 真正抽观点时，只能读取这个拆解目录里的现成观点文件；
- 不允许再回头从播客原文里重新拆观点；
- 不允许把播客原文当成观点来源直接引用。

如果找不到对应拆解目录，必须停止并提示：

```text
当前还不能开始生成。

这篇 B 播客还没有对应的播客拆解目录。
请先补齐 `01_热门播客/02_播客拆解` 下的对应拆解结果后，我再继续。
```

## 最终输出

统一输出到：

`03_爆款文案/01_生成文案`

输出形态固定为一篇 Markdown 文件，内部只保留这两块：

1. `爆款开头复刻`
2. `三条主线方案`

文件名格式固定为：

`YYYYMMDD_HHMM_短视频标题.md`

标题要求：

- 文件名主体使用最终默认主标题；
- 默认主标题来自 3 条主线方案里最稳的一条；
- 不是原稿标题直抄；
- 不是 BK 开头卡片文件名拼接；
- 直接对应这条短视频的核心命题；
- 仅做必要的 Windows 非法字符清理。

## 核心执行顺序

### 第一步：检查三项输入是否齐全

先检查：

- `B播客原文`
- `BK 开头卡片`
- `观点数量`

只有三项都齐全，才能继续。

### 第二步：确认结构输入是不是编号文件

如果结构输入不是 `02_资产中心/05_爆款开头库/BK...md` 这一类爆款开头卡片，而是 `02_对标视频/01_对标视频原文/...txt` 这种对标原文，必须停止，不允许继续。

### 第三步：先学习 BK 开头卡片

读取用户指定的 `BK` 爆款开头卡片文件，但只提取和开头复刻直接相关的结构资产，例如：

- 原文前5句；
- 逐句核心功能；
- 逐句写作结构；
- 五句推进逻辑；
- 五句结构骨架；
- 句式模板；
- 适合承载的论证方式；
- 调用匹配规则。

不要把 BK 开头卡片当成全文正文模板使用。

也不要读取 `02_对标视频/01_对标视频原文/...txt` 再重新拆。

### 第四步：根据 B 原稿定位拆解目录

根据用户指定的 `B` 原稿，去定位它在 `01_热门播客/02_播客拆解` 下对应的拆解目录。

若存在：

- 读取该目录下的 `00-推荐理由.md`；
- 读取该目录下的 `00-观点总览.md`；
- 读取多个“编号 + 观点标题”的观点文件。

若不存在：

- 直接停止；
- 提示用户先补齐这篇播客的拆解目录；
- 不允许在当前 skill 里回头重拆原文。

观点只能来自这篇 `B` 播客自己的拆解目录，不允许跨目录抽取。

### 第五步：建立观点池

从观点文件中抽出本次主线方案可用的观点池。

每条可用观点至少保留这些信息：

- 全局编号；
- 观点一句话；
- 所属观点文件名；
- 所属观点文件相对路径；
- 对应的 Obsidian wikilink；
- 拓展标签；
- `2到4个结构化拓展点`；
- 该观点更偏哪类作用：
  - 问题抛出
  - 原因解释
  - 认知反转
  - 风险放大
  - 机会确认
  - 现实验证
  - 行动建议
  - 结论收束

### 第六步：先输出爆款开头复刻

先输出一张只负责开头复刻的表：

| 原文结构 | 原文内容 | 输出后内容 |
|---|---|---|

约束：

- `原文结构` 只写结构动作标签；
- `原文内容` 只写 BK 开头卡片里对应句子的原句；
- `输出后内容` 只写按 `B` 播客内容复刻出的新句子；
- 不额外加旧版的“来源”“说明”“对应来源”“本点小结构”等列；
- 不把正文观点写进这张表；
- 不在表后重复生成一遍完整开头。

额外硬约束：

- 不能只按结构动作的意思重写；
- 必须结合开头卡片里的 `五句结构骨架`、`句式模板` 和 `调用匹配规则` 来复刻；
- 必须尽量复刻原文的长短句交替、停顿位置和句式推进；
- 如果原文这一行是短句，就优先复刻成短句；
- 如果原文这一行是“设问 -> 解释”，就不要直接压成一个解释长句；
- 如果原文这一行只是一个感受句、评价句或收口句，就不要额外再补第二层解释；
- 目标是尽量保留原文像人说话的节奏，而不是把每个结构位都写成标准解释句。

### 第七步：再输出三条主线方案

每次固定输出 3 条主线。

每条主线只保留两部分：

1. 一句 `主线`
2. 一张四列表

主线写法固定为：

```md
## 主线方案 1

### 主线
这里用一句话写清这条短视频真正讲的主线
```

然后紧接一张表：

| 序号 | 逻辑关系 | 选用观点 | 对应来源 |
|---|---|---|---|

列定义固定为：

- `序号`：`1`、`2`、`3`……
- `逻辑关系`：只用 4 到 6 个字概括，作为标签使用；
- `选用观点`：直接写这条观点的观点原句，以及它下面的关键判断 / 反常识点 / 关键动作等结构化条目；
- `对应来源`：单独写这条观点对应的来源文件，并做成一个 Obsidian 可点击链接。

推荐的 `逻辑关系` 标签示例：

- 问题抛出
- 原因解释
- 认知反转
- 风险放大
- 机会确认
- 现实验证
- 行动建议
- 结论收束

## Obsidian 链接约束

`对应来源` 这一列固定优先使用一个直接链接：

```md
[[相对路径/观点文件名.md]]
```

要求：

- 链接目标必须指向当前 `B` 播客拆解目录下的真实观点文件；
- 不额外补第二段展示文字；
- 不显示纯路径；
- 不写成普通 URL；
- 不跨播客引用别的目录。

如果当前实现阶段无法稳定拿到相对路径，退化方案为：

```md
[[003-长期主义不是熬，而是持续积累确定性]]
```

但正式生成时，优先使用带相对路径的完整 wikilink。

## 主线生成规则

主线方案的生成逻辑固定为：

- 先定一句话主线；
- 再按这条主线拆出一条自洽的逻辑链；
- 再从当前 `B` 播客的观点池里反向抽取最能支撑这条逻辑链的观点；
- 观点允许重排；
- 不要求忠于原文出现顺序；
- 只要求整条主线讲述顺序合理、逻辑自洽。

选择标准固定为：

- 优先服务主线逻辑；
- 优先选强支撑观点；
- 不为凑数硬塞弱相关观点；
- 所有观点都必须来自当前这篇 `B` 播客自己的拆解结果。

## 开头复刻规则

- 开头必须遵循指定 BK 开头卡片的真实核心功能和五句结构骨架；
- 要同时复刻：
  1. 结构动作
  2. 句长节奏
  3. 口语推进
-  4. 五句结构骨架里的句式推进和变量位置
- 开头优先复刻 A 的句子推进方式，而不是先解释清楚再展开；
- 短句优先；
- 长句只在 A 原结构本身就是长句时才允许跟进；
- 必须保留长短句交替，不能把连续短句改成解释型长句群；
- 对应结构位时，本稿每一行优先生成一句或半句，不默认扩成一段；
- 必须先参考 `五句结构骨架` 和 `调用匹配规则`，再落具体句子；
- 若 `B` 缺少某个动作所需素材，优先标记缺失或换成同功能短句，不允许用长解释段硬补；
- 如需写人物值得听、内容为什么值得听、现在为什么值得听，优先调用对应播客拆解目录下的 `00-推荐理由.md`，但不得编造新事实。

## 强制约束

- 只把结果写入 `03_爆款文案/01_生成文案`；
- 不得写入 `03_爆款文案/02_成稿文案`；
- 不得在三项输入缺失时自行猜测；
- 不得把 BK 开头卡片当全文正文模板用；
- 不得读取对标视频原文后自行重新拆结构；
- 不得读取 B 播客原文后自行重新拆观点；
- 不得跨播客抽取观点；
- 不得虚构案例、数字、人物成就和外部事实；
- 不得直接照抄 A 对标文案的具体内容；
- 不得把连续短句写成解释型长段；
- 不得恢复旧版正文结构映射表；
- 不得输出与当前模板不一致的旧字段。
