# 爆款开头复刻与主线方案生成规则

## 一、调用门槛

- 只有同时提供 `B播客原文`、`BK爆款开头卡片`、`观点数量`，才允许开始生成；
- 缺少任一项，都必须停止；
- 不允许猜原文；
- 不允许猜结构；
- 不允许猜观点数量；
- 不允许缺项时先生成一部分；
- 不允许把对标视频原文当成结构输入。

固定提醒文案：

```text
当前还不能开始生成。

还缺少以下必要输入：
- B播客原文：是否已提供
- BK 开头卡片：是否已提供
- 观点数量：是否已提供

请补齐这三个要素后，我再继续调用这个 skill。
```

如果用户给的是对标视频原文，而不是 `BK` 爆款开头卡片，固定提示：

```text
当前还不能开始生成。

你提供的是对标视频原文，不是 BK 开头卡片。
请改为提供 `02_资产中心/05_爆款开头库/` 下面的 `BK...md` 文件后，我再继续。
```

## 二、B 原稿与观点来源

- `B播客原文` 只用来定位 `01_热门播客/02_播客拆解` 下对应的拆解目录；
- 真正抽观点时，只能读取对应拆解目录下的观点文件；
- 不允许回头从 B 播客原文里再重新拆观点；
- 不跨播客、不跨目录、不跨主题混用观点；
- 每条观点至少要能对应到一个真实观点文件；
- `选用观点` 一列默认直接输出观点原句和它下面的结构化条目，而不是只输出观点标题；
- 如果需要人物、内容、时机的推荐表达，只能从 `00-推荐理由.md` 里取。

如果找不到对应拆解目录，必须停止并提示：

```text
当前还不能开始生成。

这篇 B 播客还没有对应的播客拆解目录。
请先补齐 `01_热门播客/02_播客拆解` 下的对应拆解结果后，我再继续。
```

## 三、结构来源

- 开头只来自指定 `BK` 爆款开头卡片中的前5句结构；
- 不照抄 A 文案的具体人物、公司、数据、原句和案例；
- 目标不只是复用“怎么开场”，还要复用“怎么推进”和“怎么停顿”；
- 如需写人物值得听、内容为什么值得听、现在为什么值得听，优先调用对应播客拆解目录下的 `00-推荐理由.md`；
- 不允许读取 `02_对标视频/01_对标视频原文/...txt` 再临时重拆结构。

## 四、先学结构，再复刻开头

- 正式输出前，必须先完整学习 `BK` 爆款开头卡片；
- 至少要提取：原文前5句、逐句核心功能、逐句写作结构、五句推进逻辑、五句结构骨架、句式模板、适合承载的论证方式、调用匹配规则；
- 学完之后，先输出 `爆款开头复刻` 表；
- 不允许跳过这一步直接开始列主线。

`爆款开头复刻` 表固定只有 3 列：

| 原文结构 | 原文内容 | 输出后内容 |
|---|---|---|

约束：

- `原文结构` 只写结构动作标签；
- `原文内容` 只写 BK 开头卡片里对应句子的原句；
- `输出后内容` 只写按 `B` 播客内容复刻出的新句子；
- 不增加“来源”“说明”“本点小结构”“对应来源”等旧列；
- 不把正文观点写进这张表；
- 不在表后重复生成一遍完整开头。
- 不能只按结构定义去翻写；
- 必须结合 `五句结构骨架` 和 `调用匹配规则` 来复刻；
- 必须尽量保留原文的长短句交替、停顿感和句式推进；
- 原文是短句的位置，优先继续用短句；
- 原文是“设问 -> 通俗解释”的位置，不要压成一个说明性长句。
- 原文如果只是单独一个感受句、评价句或收口句，就不要额外续写第二句解释。

## 五、三条主线方案

- 每次固定输出 3 条主线方案；
- 每条主线只保留一句 `主线`；
- 主线下面紧跟一张四列表：
  - `序号`
  - `逻辑关系`
  - `选用观点`
  - `对应来源`

格式固定为：

```md
## 主线方案 1

### 主线
这里用一句话写主线

| 序号 | 逻辑关系 | 选用观点 | 对应来源 |
|---|---|---|---|
| 1 | 问题抛出 | 观点：……<br>2个误区：<br>1. ……<br>2. …… | [[相对路径/001-xxx.md]] |
```

## 六、逻辑关系标签

- `逻辑关系` 只用 4 到 6 个字概括；
- 它是标签，不是解释段；
- 推荐标签包括：
  - 问题抛出
  - 原因解释
  - 认知反转
  - 风险放大
  - 机会确认
  - 现实验证
  - 行动建议
  - 结论收束

## 七、主线与观点抽取规则

- 先定一句话主线；
- 再拆出一条自洽的逻辑链；
- 再从观点池里反向挑选最能支撑这条逻辑链的观点；
- 观点允许重排；
- 不要求忠于原文出现顺序；
- 只要求整条主线讲述顺序合理、逻辑自洽；
- 不为凑数硬塞弱相关观点；
- 所有观点都必须来自当前这篇 `B` 播客自己的拆解结果。

## 八、Obsidian 链接规则

`对应来源` 一列优先使用一个直接链接：

```md
[[相对路径/观点文件名.md]]
```

要求：

- 链接目标必须指向当前 `B` 播客拆解目录下的真实观点文件；
- 不额外补第二段展示文字；
- 不显示纯路径；
- 不写成普通 URL；
- 不跨播客引用别的目录。

如果当前阶段无法稳定拿到相对路径，退化为：

```md
[[003-长期主义不是熬，而是持续积累确定性]]
```

## 九、语言与忠实度原则

- `输出后内容` 要顺口、清楚、方便继续加工；
- 主线要短；
- 逻辑关系要短；
- 多用短句；
- 开头保持推进感，不写成长解释；
- 不得编造上游没有的新事实；
- 不得把开头复刻表写成说明文摘要；
- 不得恢复旧版正文映射写法。
