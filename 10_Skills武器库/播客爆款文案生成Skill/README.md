# 播客爆款文案生成Skill

这是一个可公开安装的独立 Skill，负责把：

- 一个指定的 `BK` 爆款开头卡片文件；
- 一篇指定的 `B` 播客原稿；
- 一个用户手动给出的观点数量；
- 一个用户明确提供的输出目录；

组合成一份“爆款开头复刻 + 三条主线方案”的中文短视频方案稿。

## 它解决什么问题

前面两层已经各自解决了两个问题：

1. `爆款开头拆解Skill`
   负责把 A 对标短视频的开头拆成统一的爆款开头卡片文件；
2. `播客内容模块拆解Skill`
   负责把 B 播客原稿提前拆成标准观点目录和观点文件；

但真正生成文案时，还缺中间这一层：

> 怎么把 A 的爆款开头卡片文件、B 的观点文件、B 的推荐理由，拼成一份真正能讲出来、还能直接看开头复刻和三条主线的短视频方案稿？

本 Skill 就是专门补这个缺口。

## 这次锁死的规则

1. 开头继续按 `原文前5句`、`逐句拆解`、`五句推进逻辑`、`五句结构骨架` 做强模仿
2. 结构输入必须是正式 `BK*.md` 开头卡片文件，不能是对标视频原文
3. `B播客原稿` 只用来定位对应的播客拆解目录
4. 真正抽观点时，只能读取播客拆解目录里的现成观点文件
5. 先输出开头复刻，再输出三条主线方案
6. 开头复刻必须结合 `五句结构骨架` 和 `调用匹配规则`，尽量复刻原文长短句和句式推进
7. 主线里的观点允许重排，但必须逻辑自洽
8. 主线表拆成四列，来源链接单独一列

## 结果长什么样

输出是单个 Markdown 文件，但文件内部固定分成两层：

1. 爆款开头复刻
2. 三条主线方案

开头部分固定只保留三列：

- 原文结构
- 原文内容
- 输出后内容

主线部分固定为：

- 一句主线
- 一张“序号 / 逻辑关系 / 选用观点 / 对应来源”表

其中 `选用观点` 要放完整观点内容，`对应来源` 只放一个 Obsidian 可点击链接。

文件名格式固定为：

`YYYYMMDD_HHMM_短视频标题.md`

## 推荐调用方式

```text
调用“播客爆款文案生成Skill”。

爆款开头卡片文件是：<BK文件绝对路径>
B播客原稿是：<播客原文绝对路径>
播客拆解目录是：<拆解目录绝对路径>
输出目录是：<输出目录绝对路径>
这次生成 6 条观点。

这里的结构输入必须是正式开头卡片文件，不能是对标视频原文。
你要先理解这个开头卡片里的前5句推进方式，再开始写。

B播客原稿只用来核对用户指定的拆解目录。
真正抽观点时，只能读取这个拆解目录里的现成观点文件，不能回头重新拆原文。

开头按正式爆款开头卡片来写，但不要照抄A文案的具体内容。
同时开头要强模仿A的句长、停顿、长短句交替和口语推进，不要写成长解释。
而且不能只按结构意思去重写，必须结合 `五句结构骨架` 和 `调用匹配规则` 来复刻句式推进。
如果要讲人物为什么值得听、这期为什么值得听、为什么现在值得听，优先调用这篇B播客拆解目录里的00-推荐理由.md。

先输出“爆款开头复刻”表，只保留：
原文结构 / 原文内容 / 输出后内容

然后输出 3 条主线方案。
每条主线都只保留一句主线。
主线下面紧跟一张表：
序号 / 逻辑关系 / 选用观点 / 对应来源

逻辑关系只用 4 到 6 个字概括。
选用观点要放完整观点内容，不要只写一句标题。
对应来源单独放文件链接，只放一个 Obsidian 可点击链接。
观点允许重排，不要求忠于 B 播客原文顺序，但必须逻辑自洽。

生成一个适合这条短视频的独立标题，保存到用户指定的输出目录。
```

## 安装

优先把整个 `播客爆款文案生成Skill` 目录直接安装到 Codex 的本地 skills 目录中。

不要只复制 `SKILL.md`，因为模板、说明、示例和规则文件需要一起保留。

生成后运行：

```text
python scripts/validate_output.py <输出Markdown文件>
```

校验未通过时不得把结果视为正式产物。
